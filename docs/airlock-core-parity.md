# Airlock core prototype mapping

Pinned SS14 source is `c9df5ef5d675b0d1d226828bddf6b78c28502d91`.

The local typed prototype composes the supported `Door`, `Airlock`, `DoorBolt`, `ApcPowerReceiver`, and `WiresPanel` data from `Resources/Prototypes/Entities/Structures/Doors/Airlocks/base_structureairlocks.yml` (`Airlock` parent `BaseStructure`). Verified defaults carried into the local definition: APC demand 20 W; auto-close enabled after 5 s; safety enabled; bolt lights enabled; opening/closing phase-one 0.4 s and phase-two 0.2 s; deny 0.45 s; 15 blunt crush damage and two-second stun; unbolted/bolted pry multipliers 9/3. `DoorComponent.cs`, `AirlockComponent.cs`, `DoorBoltComponent.cs`, `SharedDoorSystem.cs`, `SharedDoorSystem.Bolts.cs`, and server `DoorSystem.cs` are the corresponding data consumers. `DoorSystem.SetCollidable` sets Airtight from collidability. Bolts veto normal open/close/deny and pry; restored receiver power re-engages bolts only when the bolt wire is cut.

Renderer visual adaptation: controller phase drives horizontal 3D leaf travel using resolved phase durations. All cuboid faces use a uniform gray base; only front/back planes receive explicit static-closed sprite UV patches. Frame strips and the two leaves map their closed canvas regions without applying animated 2D opening/closing frames to moving geometry. This is a Minecraft rendering adaptation, not an upstream geometry/component claim.

Deliberate local adaptations: the prototype's cable reach (3 blocks) is an explicit local power-runtime policy, not asserted upstream receiver reach. The structure is represented by lower/upper Minecraft blocks with one root controller BE. The pinned `Resources/Prototypes/Wires/layouts.yml` Airlock layout resolves eight actions in source order: two PowerWireAction entries (30 s and 15 s), LogWireAction, DoorBoltWireAction, DoorBoltLightWireAction, DoorTimingWireAction, DoorSafetyWireAction, and AiInteractWireAction. The typed local layout has eight resolved entries and opaque server-randomized slot IDs rather than exposing action identities to the client; persisted root state and authoritative server snapshots carry physical cut/mend status. AIA/Log lamps report circuit continuity (On intact; Mend restores On; Off cut), but no AI/log service is implemented: Log pulse's 30-second disable/event and AI interaction remain unsupported; the local placeholder pulse is a no-op preserving cut state. They do not create logging, AI, inventory-rights, or remote-interaction components. Power's shared pulse behavior and the existing four supported door actions remain functional. No unsupported SS14 runtime components are invented. Department access/electronics, AI, radio/networking and construction remain omitted. Crowbar tool quality/speed resolves through the typed local tool prototype. Entity collision is the local obstruction test; unsafe closure routes damage through the existing typed damage/status systems. Atmosphere topology follows the two blockstate openness flags, so both cells seal/pass independently and opening/closing invalidates the existing topology tracker.
