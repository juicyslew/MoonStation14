The owner's target is **three simultaneous independent popups total**, shared by arbitrary storage hosts: worn bag, worn belt, and/or reachable world storage (for example, a future briefcase). Three distinct world hosts may occupy all three slots; a fourth host (including a bag) is denied until a visible window closes. There is no per-kind quota, and hidden/closed windows do not consume a slot; reopening one still observes the same three-visible-window limit. Window kind affects host identity/lookups and geometry only, not quota. This deliberately differs from the cited keybind defaults; SS14's cited V/Shift+V mapping does not establish three-window support. No world-storage host/open protocol exists by virtue of this note. World popup support is gated on a real host/entity, reach validation, session/token binding, and authoritative snapshot. Do not fabricate that support or show stale world contents as live.

## Target controls and visual contract

- Use tiny, independent SS14-styled popup windows, not vanilla buttons/menus. Reuse the project's `MachineWindowRenderer` and window geometry for chrome, title/close affordance, placement and safe bounds; bespoke storage controls draw inside that frame. Window dragging must not steal item drags. Each popup is independently dismissible and can coexist without obscuring hands/equipment.
- Keep persistent item-icon indicators along the bottom HUD for both hands and equipment (including worn bag and belt). They reflect authoritative item identity/empty state, not a second mutable inventory. Open windows and HUD indicators reconcile from the same current state.
- Match the owner's **TOGGLE CURSOR** choice: one explicit toggle enters pointer mode and toggles back out; do not require holding a modifier. WASD movement remains usable in both modes. Camera look is available only outside pointer mode; in pointer mode mouse motion targets UI rather than turning the camera. Define an unambiguous toggle key and focus/escape behavior during implementation, then test it with movement. This is an owner interaction requirement, not an upstream SS14 default claim.
- Attribute any reused SS14 sprite/pickaxe art to its verified source and **CC-BY-SA-3.0** terms, with per-asset notice and provenance. Verify the particular file before import; the license is not blanket permission for unverified art. Prefer existing/local geometry if provenance is uncertain.

## Staged implementation and authority contract

1. **Presentation:** lay out and manually inspect the persistent two-hand/equipment icon row and independent bag/belt popups using current snapshots. Existing 10d grid previews may render, but no client-only visual may claim a transfer succeeded. Keep absent/stale data visibly unavailable.
2. **Authenticated worn-storage grid actions:** enable actual drag intents hand→equipment storage, hand→grid, grid→hand, and in-grid reposition/rotation. Client may render a provisional placement/drag ghost, including a red invalid-collision preview; it must remain explicitly provisional until the authoritative response/snapshot. Never remove the source item or display a confirmed destination while a request is pending. On rejection/timeout restore from authority, not a guessed inverse operation. Keyboard selection plus move/place/rotate/cancel is a complete fallback to every drag action.
3. **Server validation:** a new authenticated action is required for grid→hand and every in-grid move (the 10d note says real slots currently lack drag/drop). Validate actor/body/equipment ownership, source and destination, item identity, exact observed revision/token, old anchor and old rotation, requested new anchor/rotation, bounds, overlap/collision, and current item eligibility atomically against current server state. Reject stale/mismatched old placement rather than moving an item from a client-asserted location. Return/re-publish an authoritative bounded snapshot after acceptance and rejection; do not add a client-authoritative shortcut.
4. **World popup, separate gate:** only after a real world-storage owner exists. Open/request must bind an authenticated session to the actual entity and verify current reach/interaction eligibility server-side. Every action rechecks session, entity existence, reach, ownership and revision; close, range loss, despawn or entity replacement invalidates the session. Snapshot identity must identify that exact world container. Item despawn is a separate world-ownership change, not an ordinary grid move or implicit UI close; reconcile it through authoritative world ownership and invalidate/reject affected placements safely. No world host or support is promised here.

Provisional visuals must never imply server ownership. During latency the source remains visible (with a pending marker/ghost if useful); only an authoritative snapshot confirms it moved. On stale snapshot, rejection, close/reopen, range loss or entity despawn, discard pending presentation and reconcile from a fresh valid authority snapshot. Keep independent windows keyed to their container identity/session, never just their screen position or title.

## Acceptance checklist

- Connected manual run with at least two clients: both clients see hand/equipment icons and bag/belt windows converge after transfers; no ghost-only success, disappearance while pending, duplication or stale window contents. Confirm concurrent windows, close/reopen and changed revisions.
- Toggle cursor on/off; WASD works in either mode; camera turns only outside pointer mode. Check pointer hit testing, world Use/left-click pickup vs UI clicks, window drag vs item drag, focus loss, escape/close, and no accidental world interaction while operating a popup.
- Verify Q drop; Shift+B and Shift+E equip; V bag popup and Shift+V belt popup against the pinned keybind references or document intentional local remapping. Pickup remains world Use/left-click, not G. Verify icon states and each window remain coherent after equip/unequip/drop.
- Exercise hand→bag/belt, hand→grid, grid→hand, in-grid move and rotation; valid/invalid overlap with red preview; rejection, stale revision, wrong old anchor/rotation, occupied destination, and keyboard fallback. Rejected actions must preserve/restore authoritative item placement.
- For any later world-window implementation, test in-range open, out-of-range/reach loss, wrong entity/session/token, close/reopen, entity replacement/despawn, simultaneous world and worn windows, stale snapshot and separate item despawn/world-ownership change. Until this owner exists and passes these checks, no reachable-world popup acceptance is claimable.
- Attribute sprites/pickaxe per file, and check provenance/license notices in the delivered distribution.

There is **no old-save compatibility requirement** for this acceptance; the 10d owner plans a fresh world/nonpersistent server. This note requires no migration of old filled saves. The machine visual kit supplies reusable window geometry/chrome and widget patterns, not live inventory transfers, an inventory authority contract, a three-world-window host, or the ability to walk while a vanilla screen is open. Do not claim otherwise. This note specifies a target and acceptance gates; it does not assert connected acceptance is complete.
