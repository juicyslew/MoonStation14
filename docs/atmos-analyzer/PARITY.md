# Handheld gas analyzer composition and behavior

The pinned SS14 checkout is `c9df5ef5d675b0d1d226828bddf6b78c28502d91`. In
`Resources/Prototypes/Entities/Objects/Specific/atmos.yml` (`GasAnalyzer`, lines
1–40), `GasAnalyzer` directly inherits `BaseItem`; `Resources/Prototypes/Entities/Objects/base_item.yml`
(`BaseItem`, lines 1–46) has no parent. BaseItem provides small item size, animated
sprite, clickable/outline interaction, dynamic physics (half-block fixture, density
20, item mask), gravity, damage and examine behavior. The analyzer composes its
sprite, GasAnalyzer and ActivatableUI (in-hands-only, single-user, does not require
active hand), bound UI, appearance/visualizer, price 80, steel 400, glass 100 and
guide-help metadata. It has no power or storage component.

Upstream `Content.Shared/Atmos/Components/GasAnalyzerComponent.cs` has no polling
field; server `Content.Server/Atmos/EntitySystems/GasAnalyzerSystem.cs` sets a
one-second update cadence and an initial accumulated frame time of 2.01 seconds.
Its UI has environment/device tabs and a split bar graph; species are descending
by moles and omitted at or below 0.01 mol. It reports volume, pressure, K/°C,
moles and percent. The world environment is always included; target scans concern
entity events/node pipes, not arbitrary map tiles.

Local typed `gas_analyzer` profiles resolve inheritance and drive the held item
consumer. The one-second cadence and 0.01 mol cutoff are retained. Six-block
remote cell selection, initial one-block distance, and transparent-cell inspection
are deliberate Minecraft adaptations (not upstream parity); later session/UI work
must use controlled-body selection and shared examination vision. The finite-cell
sample is detached/read-only and does not create rooms or topology. Existing
`item_footprint/atmosphere_analyzer.json` preserves the small footprint. No
unsupported upstream components, power cost, or second gas store is added. The
registered item model now uses the verified, unedited SS14 `icon` state at
`assets/moonstation14/textures/item/atmosphere_analyzer.png`; its adjacent notice
records the pinned source, hashes, CC-BY-SA-3.0 and exact Baystation/onesch credit.
The upstream working animation and in-hand sprites are intentionally not imported;
this Minecraft item uses a static inventory icon.

The current server session uses ordinary `BodyHandRequestService` `USE_IN_HAND`
admission and the exact `LiveHands` item token. It remains valid with that token in
either body hand and closes on body/epoch/dimension or source invalidation. Payload
controls carry only bounded distance and correlation; the server derives target
cells from the controlled body's eye/look and `ExamineVision` transparency. Both
local and remote readings come from loaded-only `AtmosphereService.readAtmosphere`.
The server snapshot/control protocol is a Minecraft data-window adaptation, not
the upstream bound-UI transport. Repeated use of the same valid body/epoch/dimension
and held token reuses the existing session and distance rather than opening a new
generation. The displayed item name is **Gas Analyzer**; its existing registry ID
`moonstation14:atmosphere_analyzer` is unchanged.

Presentation is a nonmodal `OrderedPaint` production workspace using the existing
`MachineWindowRenderer`, `WindowChromeButtons`, `PointerWorkspaceLayers`, and
`StoragePopupScreen` z/input host. The same `GasAnalyzerPaint` drives live and CPU
preview. Numeric display reuses `ExamineNumbers`; species names reuse the shared
`gui.moonstation14.gas.*` translations and palette uses `GasVisibility.displayTint`.
The compact window caps at 152×108 GUI pixels, uses 0.7× text and separates the gas
list backing from the pressure/volume/temperature summary. **At you** shows local
environment gas without a distant outline; **Target** is the default and displays
the selected look-ahead cell. These labels do not imply SS14 remote-mode parity.
The target graph waits until cell, distance, session and control sequence match.
Locked-cursor wheel input changes distance before pointer hit-testing; an unlocked
pointer can scroll either tab's gas list. There are no distance +/− buttons.
Shared workspace ordering owns one paint pass above hand/equipment GUI items,
including read-only chat rendering; this does not grant chat pointer ownership.

The post-R20 candidate passed 58 focused JVM tests in 18 classes and all three
compile tasks. Eight selected production CPU images were independently opened;
subsequent input/proof corrections regenerated byte-identical images. Corrected
focused native diagnostics passed the actual registered through-glass sample,
glass selector and individual-demo/manifold sequence (3/3 selected cases).
Current readiness, native GPU/input/audio and owner acceptance remain unverified;
the earlier R20 feature PASS does not validate these later changes.
