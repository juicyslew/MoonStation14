## Model and incomplete behavior

- Pressure is computed from moles per fixed 1 m³ cell and temperature using the ideal-gas relation. Gas-specific heat capacity determines stored thermal energy.
- Sparse chunk overrides store finite cell states. There is no room object, identity, aggregate, or automatic fill. Every block cell inherits implicit ambient until changed; changed cells have independent overrides. Gas/thermal energy exchange occurs only across open six-neighbor faces; diagonal corner contact is not connected. Pressure is derived, not separately diffused. Heat transfers via gas only. Sealing in vacuum does not auto-fill.
- Default COMMON config behavior is `enableAtmospherics = false`, with restart required. While disabled the atmosphere service performs no reads/writes/processing, though the registered device ticker makes a cheap enabled check each server tick. `atmosphereVacuumDimensions = []` means every dimension is breathable by default. Use an isolated new world/dimension; saved-world policy changes require migration planning.
- Active exchange is pairwise along six faces and transfers gas/thermal energy locally. Isolated pair transfer is conservative, but FIFO neighbor order is biased; this local pressure equalization is not room-wide equalization or SS14 parity.
- Topology uses world-aware collision fallback: full collision blocks and closed doors/trapdoors/gates seal; open variants pass. Partial shapes pass, face/orientation airtightness is unsupported. Placement/removal can create or destroy implicit ambient gas/mass because absent cells are not materialized. Conservation semantics remain unresolved (M2 blocker).
- Empty vacuum has no thermal capacity/energy and will not absorb heat. Temperature is world-cell gas temperature only; no solid heat transport or body temperature exists.
- No UI, pressure forces, lungs, respiration, reactions, pipes, fire, solar heat, or complete server-world tests. No 20-player benchmark or performance profile exists. Full SS14 parity is not claimed.

## SS14 comparison and deviations

SS14 map/grid atmosphere uses finite tile mixtures with implicit map/space defaults, and active neighbor diffusion/heat processing. LINDA and Monstermos are SS14 grid-atmosphere solver strategies; neither is implemented locally. The Minecraft implementation instead uses sparse fixed-1-m³ block cells, dimension ambient for missing overrides, and local active pairwise diffusion along six faces. It has no room identity/aggregate, and sealing an enclosure in vacuum does not auto-fill. Reference paths include `Content.Shared/Atmos/GasMixture.cs`, `Content.Shared/Atmos/Atmospherics.cs`, `Content.Shared/Atmos/MapAtmosphereComponent.cs`, `Content.Server/Atmos/EntitySystems/AtmosphereSystem.{GridAtmosphere,Processing,LINDA,Monstermos}.cs`, and `Resources/Prototypes/Atmospherics/gases.yml`. Review in external checkout `C:\Users\William\Documents\SS14-dev\space-station-14` was targeted, not a full audit or parity evidence. Other deviations: hard-coded local gas capacities, FIFO pair-order bias, zero-capacity vacuum (no cold sink), and no pressure forces, UI, chemistry, pipes, fire, solar/solid heat transport, or body/respiration coupling. No full SS14 parity is claimed.
