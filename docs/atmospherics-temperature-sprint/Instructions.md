# Atmospherics and Temperature Sprint

## Purpose, scope, and current status

This document describes the experimental Minecraft 1.21.1 / NeoForge 21.1.224 world-gas foundation and the ordered work required before it can be accepted. The sparse server-cell runtime and startup safety gate exist, and four registered placeholder test devices, producer/sink APIs, and focused pure device tests are implemented. **M3 acceptance remains OPEN**, pending server-world automated tests and owner smoke. No SS14 parity, room simulation, entity respiration, or body-temperature system is claimed. `Oxygenate` and `AdjustTemperature` remain unsupported because the relevant entity owners do not exist.

`enableAtmospherics` is a COMMON config setting and defaults to `false`. Both it and `atmosphereVacuumDimensions` are sampled at `ServerAboutToStartEvent`, before spawn chunks load; enabling or disabling requires restart. While disabled, the service does no reads, writes, or processing. The four registered placeholder blocks remain inert, though their shared server-side block-entity ticker makes a cheap enabled check each tick. `atmosphereVacuumDimensions` optionally lists dimensions with vacuum ambient; empty/default means breathable ambient in every dimension, including the End and custom dimensions. Prefer an isolated new world/dimension for testing. Changing ambient policy in a saved world can reinterpret every cell without an explicit override and must not be done without an owner-approved migration plan.

Example `config/moonstation14-common.toml` settings (restart after changes):

```toml
enableAtmospherics = true
atmosphereVacuumDimensions = ["minecraft:the_end"]
```

The vacuum list is optional; omit it or set `[]` to keep all dimensions breathable.

## Current model and boundaries

- A Minecraft block position is one fixed 1 m³ gas cell. Pressure is derived from moles and temperature using the ideal-gas relation; mixtures have gas-dependent heat capacity and thermal energy.
- Cells without explicit chunk-attachment overrides read dimension ambient: 21% oxygen / 79% nitrogen at 293.15 K and 101.325 kPa by default, or zero-gas nominal 2.7 K ambient in configured vacuum dimensions. Sparse overrides can store distinct finite states in neighboring cells.
- There is **no room object, identity, aggregate, or auto-fill operation**. Think of a 3D arrangement as independent block cells: each inherits implicit ambient until changed, and each changed cell is an independent override. Gas and thermal energy exchange only across open six-neighbor faces; diagonal corner contact does not connect cells. Pressure is derived, not independently diffused. Heat transfer is through gas only; vacuum has no cold heat sink. A sealed enclosure is not a room-level state, and sealing in vacuum does not fill it. Building/removing walls can currently create or destroy implicit ambient gas/mass; conservation semantics are unresolved.
- The active solver processes neighbor pairs along the six block faces when accessible/passable. It is a local pairwise approximation, not SS14 parity or room-wide pressure equalization. Isolated pair transfers are conservative, but FIFO multi-neighbor processing is order-biased. Closed doors, trapdoors, and gates seal; open ones pass. Full collision blocks seal; partial shapes are treated as passable and airtight face/orientation is not modeled.
- Empty vacuum has zero heat capacity and thermal energy; it cannot act as a cold sink. There is no solid heat transport, pressure force, fire/reaction, pipe, or entity/body heat transport. Active work has per-tick caps, but deferred overflow/deduplicated queue memory is unbounded. No 20-player benchmark has been run.

## SS14 comparison (reference, not a parity target)

SS14's map/grid atmosphere uses implicit map/space defaults together with finite gas mixtures on grid tiles. Its active atmosphere processing diffuses neighboring tile mixtures and exchanges heat. LINDA and Monstermos are distinct alternative solver strategies in SS14's grid-atmosphere processing; neither solver is implemented here. This Minecraft system instead assigns a sparse fixed-volume gas cell to each block position, uses dimension ambient when no override exists, and activates local pairwise diffusion over six faces. It has neither SS14 map-grid/space ownership nor SS14 room aggregation/solver behavior. Similar concepts do not establish equivalent behavior. There is no full SS14 parity or 20-player benchmark claim.

Reference paths include `Content.Shared/Atmos/GasMixture.cs`, `Content.Shared/Atmos/Atmospherics.cs`, `Content.Shared/Atmos/MapAtmosphereComponent.cs`, `Content.Server/Atmos/EntitySystems/AtmosphereSystem.{GridAtmosphere,Processing,LINDA,Monstermos}.cs`, and `Resources/Prototypes/Atmospherics/gases.yml`. Targeted SS14 review is not a full audit; see [M1 implementation status](audits/m1-implementation-status.md).

For a measured, bounded station-region solver evaluation plan, see the [bounded station solver proposal](architecture/bounded-station-solver-proposal.md); it is a recommendation, not an implementation or performance claim.

## Implemented foundation (code presence is not acceptance)

- Core validated `GasMixture`, stable `GasType` IDs, ideal-gas pressure, and pair-transfer math under `src/main/java/com/juicyslew/moonstation14/ms14/atmos/core/`.
- Nine hard-coded gas IDs corresponding to SS14's gas names; capacities are local, not dynamically loaded from SS14 YAML.
- Sparse `ATMOSPHERE_CHUNK` attachment, version-1 codec, `sample`, positive `addGas`, `addEnergy`, plus producer/sink APIs including generic proportional `removeGasUpTo`; no species-selective extraction API.
- Server startup configuration and `AtmosphereEventHooks`; simulation/event processing is gated by `enableAtmospherics`, default false. This code path is not evidence of server integration acceptance.
- Four registered placeholder devices: breathable-air producer, proportional gas sink, heater, and cooler. Placeholder block/model/item JSON references vanilla textures only. Placement faces toward the interior: the device front points opposite the player's look direction while placing.
- With an **empty hand**, right-click any of the four atmosphere devices to request a server-chat status readout. The response reports whether atmospherics is disabled, whether the device's front-cell target is unavailable, or the sampled front cell's pressure (kPa for the fixed 1 m³ cell), temperature (K), total moles, O2 and N2 moles, and each nonzero other-gas mole amount. The request is server-only; the disabled gate short-circuits before sampling, and the readout adds no textures/UI or world mutation. Formatting tests pass, but integrated multiplayer readout behavior has not been tested.
- **Handheld analyzer (code implemented; world verification open):** `Atmosphere Analyzer` is a stack-size-1 item in the `INGREDIENTS` creative tab. Right-clicking air samples the block cell at the player's eye position. Using it on a block samples that clicked cell if it is passable; otherwise it samples the adjacent cell on the clicked face. Thus, to inspect a room through a wall, use the analyzer on the wall's room-facing surface; it cannot scan through walls. The server chat response reports the disabled-gate or unavailable-sample message, or uses the same `AtmosphereSampleFormatter` readout as the test devices. Gas is read server-side only; using the item does not mutate the world. Its model uses a static vanilla compass texture as a placeholder. Automated unit tests pass, but server-world `useOn` behavior relative to vanilla item interactions and multiplayer behavior have not been verified.
- Fixed-rate device behavior: producer adds breathable gas (21% O2 / 79% N2) at 1 mol/s, capped at 202.65 kPa; sink removes up to 1 mol/s proportionally; heater adds 2,000 J/s; cooler removes at most 2,000 J/s and floors at 2.7 K. Focused pure tests cover device rules, not server-world integration.
- Chunk-load events defer coordinates rather than performing attachment access immediately, because `ChunkEvent.Load` can arrive before a chunk reaches `FULL`. Each server post-tick makes at most 16 non-forced `FULL` chunk lookups to resume saved overrides; unresolved coordinates are requeued, deduplicated, and removed on unload. This lifecycle order is an assumption based on targeted NeoForge source review, not verified by integration GameTests.
- Deterministic FIFO active queue, 8,192-position hot queue and deferred overflow; every fourth server tick at most 128 pair edges and 512 conservatively charged inspections. Deferred queue memory is not bounded.

## Ordered milestones and gates

Complete in order; later work does not waive an earlier gate.

1. **M0 — Default-off configuration safety proof (OPEN).** Preserve `enableAtmospherics = false` by default; prove disabled worlds cause no atmosphere service reads/writes/processing and enabling is restart-only. The code gate and cheap ticker check exist, but safety proof/acceptance remains open. Verify optional `atmosphereVacuumDimensions` (empty = all dimensions use air), restart semantics, and saved-world migration warning. Prefer an isolated new world/dimension for tests.
2. **M1 — Server-world automated GameTests (OPEN).** Test actual world queries, persisted overrides, lifecycle, disabled-world behavior, and cross-chunk exchange. Construct a sealed NxMxK cell volume across chunks, isolate from dimension ambient with explicit sources, and verify six-face mixing and stable temperature/pressure. This is a room-like test only, not a room object/aggregate.
3. **M2 — Topology, persistence, and conservation (OPEN).** Define/test matter behavior for topology edits; conservation is unresolved and ambient defaults can create/remove gas. Cover airtight faces, partial blocks and doors, fluids, chunk save/load, enclosure open/close, cross-chunk and unloaded edges without force-loading, and queue resumption. Decide materialization/source-sink semantics before claiming conservation. Bound deferred queue memory and test overload behavior.
4. **M3 — Devices, analyzer, and producer/sink API (CODE IMPLEMENTED; ACCEPTANCE OPEN).** Registered producer, proportional sink, heater, cooler, APIs, fixed-rate behavior, and focused pure tests exist. Producer: 1 mol/s breathable mix capped at 202.65 kPa; sink: proportional, up to 1 mol/s; heater: +2,000 J/s; cooler: at most -2,000 J/s with 2.7 K floor. They are server-only and inert with the default-off gate (cheap ticker check still runs). Front points opposite the placement look direction. With an empty hand, right-click a device to read status in player chat: gate-disabled/target-unavailable status, or a front-cell sample of pressure (kPa per fixed 1 m³ cell), temperature (K), total/O2/N2 moles and nonzero other-gas amounts. The handheld analyzer is a stack-size-1 item in `INGREDIENTS`: right-click air samples the eye cell; use on a passable block samples that cell, or on an impassable block samples the clicked-face neighbor. To sample a room from a wall, use it on the wall's inside-facing surface; it cannot scan through walls. The server sends the disabled/unavailable message or the shared formatted sample in chat. Neither readout mutates the world or reads gas on the client. The item has a static vanilla compass-texture placeholder model. Focused automated unit tests pass, but server-world analyzer `useOn` behavior versus vanilla interactions and multiplayer behavior have not been proven. M3 acceptance awaits server-world automated tests and owner smoke testing.

   **Owner smoke guidance:** enable `enableAtmospherics = true` in `config/moonstation14-common.toml` and restart the server; config is sampled at startup. Place the device so its front points into the cell you intend to inspect: the front points opposite the direction the placer is looking, so face toward the device while placing (or verify the facing in-world). Right-click it with an empty hand and confirm the chat response. Test in an isolated new world/dimension. `atmosphereVacuumDimensions = []` (the default) means breathable ambient in every dimension; changing vacuum policy in a saved world can reinterpret cells and requires an owner-approved migration plan. The readout is for one front block cell because storage and sampling are per fixed 1 m³ cell; it is not a room aggregate, and no room object or room-wide total exists.
5. **M4 — Scale and performance (OPEN).** Profile representative active regions, bound and measure queue memory, and benchmark at or above 20 players; record solver cost, latency, queue/overflow memory and decide overload policy. No profile or benchmark exists. Owner smoke is owner-only and follows automated server gates; do not launch a server for this documentation update.
6. **M5 — Reference parity matrix and remaining-system gates (OPEN).** Build a behavior-by-behavior SS14 comparison matrix with explicit local deviations and evidence. Fire, pipes, respiration/body effects, chemistry, and other parity claims require separate implementation and tests. No full SS14 parity claim is justified.

Analyzer validation reported by its implementation worker: `.\gradlew.bat compileJava`, `.\gradlew.bat test --exclude-task compileGametestJava --tests 'com.juicyslew.moonstation14.ms14.atmos.device.*'`, and `.\gradlew.bat build --no-daemon` passed. Known blockers/limits: topology edits may create/destroy implicit ambient gas; partial collision shapes and airtight face/orientation rules are approximate; multi-cell order is biased; deferred overflow memory is unbounded; vacuum cannot absorb heat; there is no room ownership or room-level state. Cross-chunk room-like and disabled-world GameTests, owner smoke, conservation/topology edits, queue bounded-memory behavior, and performance profiling remain open. Entity respiration/body temperature, UI/sync, pressure forces, fire, pipes, reactions, and solid heat transport are not implemented.
