## Verdict

Milestone 4.5 is accepted. The attachment lifecycle, change-only mutation paths, deterministic activity scheduling, load reconciliation, and dedicated GameTest boundaries are implemented and verified. Acceptance is limited to Milestone 4.5.

## Accepted implementation summary

- `MS14Provider` entity/attachment reads are non-materializing. Detached defaults attach only after a real mutation changes state.
- Reagent metabolism is staggered deterministically across 20 ticks using server game time and entity ID.
- Empty reagent and status attachments are retained at runtime to avoid churn; empty serializers omit them from persistence.
- Immutable component snapshots and `updateIfChanged` prevent `setData`/full synchronization for unchanged reagent operations. The current metabolism, transfer/spill, puddle, vomit, and jug paths use this where relevant.
- `EntityActivity` and the nonpersistent, nonsynced `ACTIVE_SYSTEMS` attachment provide derived scheduling state. Typed `SystemLink` activity bindings and predicates feed one central server living-entity dispatcher. Status work runs before reagent work; activity is removed after final work, with no client or nonliving trackers.
- A real `EntityJoinLevelEvent` reconciles activity from authoritative loaded attachments.
- The lifecycle policy is documented in [`entity-attachment-lifecycle.md`](../architecture/entity-attachment-lifecycle.md).
- Test-only GameTests remain in the dedicated GameTest source set and are excluded from the jar, preserving the existing organization.
