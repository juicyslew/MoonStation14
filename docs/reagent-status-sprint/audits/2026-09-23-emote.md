# Emote effect audit (2026-09-23)

Production registry is exactly `cough`, `crying`, `hew`, `honk`, `laugh`,
`scream`, `weh`, `whistle`, `yawn`. It rejects arbitrary IDs and case drift at
codec load. There are no commands, reflection, or chat-trigger parsing.
Every admitted effect plays one random member of the corresponding SS14
collection from the living entity at ordinary nearby range with `VOICE`
source. Optional chat uses localized per-ID lines broadcast using tracker
delivery; disabled chat emits none. Scale does not affect either path.
Asset choices were checked against pinned-upstream `Resources/Prototypes/SoundCollections/emotes.yml`,
`disease.yml`, `Resources/Prototypes/Voice/speech_emotes.yml`, and
`disease_emotes.yml`; this port intentionally does not include chat-trigger
parsing.

This is audio/text fidelity, not full SS14 emote eligibility: all living
entities currently qualify because MoonStation has no vocal component, silicon
tag, or species profile capability model. `force` is therefore inert and never
admits nonliving entities. `showinguidebook` remains metadata only; no
guidebook projection is implemented.

2 yawn, 3 whistle, and one each weh/hew/honk). Female crying includes approved

The honk sound is an original SS14 asset but deliberately not SS14's default
