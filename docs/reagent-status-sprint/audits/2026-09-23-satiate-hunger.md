# SatiateHunger boundary audit

Hunger is a custom character-owned finite float scalar in [0,200], default 150f, persisted and synchronized through the existing attachment/component bridge. Missing data reads as 150 without materialization for unrelated entities. The temporary `thirst_eligible` entity-type tag opts players and villagers in; join initializes each only once using `[110,150)`, and an initialized exact 150 persists across reload. `SatiateHunger` applies factor times the common gate's adjusted scale; absent ArmorStand/noneligible state is not materialized by a no-op effect. HungerCondition enrichment happens only at normal EffectSystem.apply and leaves explicitly injected hunger untouched; evaluateGates remains pure.

Passive decay uses one threshold-dependent SS14 second per staggered 20-tick derived activity (bounded scheduler adaptation; no elapsed-time catch-up/time anchor). Thresholds are Overfed 200, Okay 150, Peckish 100, Starving 50, Dead 0; rates use upstream factors and clamp to `[0,200]`. Peckish/Starving persistent alerts and an independent transient 0.75 speed modifier reconcile from owner state; the starving modifier has no jetpack exception. Hunger does not use vanilla FoodData, starvation damage (upstream default is unconfigured), food UI, or full organ/stomach physiology. Character-prototype enrollment, jetpack flight handling, and elapsed-time scheduling remain limitations. Hunger attachment clone/death behavior follows the existing default attachment policy (no copy-on-death is configured); this slice does not establish a new clone policy.
