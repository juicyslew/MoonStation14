# Milestone 7: stomach ingestion isolated slice

## Implemented

- Added a character-owned `stomach` attachment with persisted/synchronized reagent-map codecs and an MS14 bridge using the existing reagent attachment/component codecs.
- Stomach capacity is 50 units. Bottle sips, HELD jug sneak-drinking, PLACED jug empty-hand drinking, and empty-hand player puddle drinking route to the stomach, never to shared `REAGENT`.
- Ingestion is server-only, eligibility checked, finite-quantity checked, and mutates source and destination only after a positive capacity admission. Full/unsupported destinations do not consume the source. Generic reagent transfers remain unchanged.
- Held jug drinking uses `JugItem.onUseTick` to call `StomachSystem.ingest` only for a player in a server level, matching the bottle callback. `JugInteractionGameTests.registeredHeldJugSneakUseIngestsAtSipBoundaryAndPreservesFullSource` exercises the registered held item, sneak-use start, pre-boundary and due callbacks, exact source/stomach delta, untouched body sugar, full-stomach source retention, and the unchanged non-sneaking throw action. Placed jug empty-hand drinking is separately covered by `registeredJugEmptyHandDispatcherIngestsAndRejectsWithoutMutation`; these tests cover distinct interaction paths.
- Ingestion converts validated source and stomach snapshots to integer hundredths using `ReagentUnits.fromMap`. It admits `min(requested cents, source cents, free stomach cents)`, then splits the admitted quantity proportionally in canonical reagent-key order with remainder cents assigned deterministically. Source subtraction and stomach addition are exact integer operations; detached cent-backed attachment snapshots are committed only for a positive admitted sip. This permits a partial sip whenever at least one cent is free, including a half-full stomach.
- Legacy positive sub-cent entries truncate to zero cents. A no-op ingestion leaves them untouched; when a positive ingestion mutates that holder, its converted attachment snapshot is persisted, discarding those sub-cent residues once. They cannot repeatedly be re-counted to create cent-scale transferred material. Requested sub-cent amounts and sources totaling less than one cent admit zero.
- Eligibility temporarily reuses `moonstation14:thirst_eligible` (players and villagers). This is explicitly a temporary character surrogate; separate opt-in tags can be introduced if stomach eligibility diverges from thirst.
- No metabolism, reactions, touch effects, or reactive ingestion effects are applied here. Ingestion-specific reactive event support is not modeled. Upstream touch/force reactions do not transfer contents into stomach/skin, so they are not falsely routed through this pathway.
- GameTests exercise the shared stomach transaction with bottle and puddle holders plus a noneligible zombie and unchanged generic transfer. A literal registered-bottle interaction test calls the actual `BottleItem.use` and `onUseTick` callbacks using an eligible server-level `Player` test double with a real `minecraft:player` entity type and inventory-held stack. A mock `ServerPlayer` was not viable without a fully configured PLAY-protocol connection: `use`/synced-attachment updates attempted network sends on the disconnected mock. The test verifies the sip boundary, exact source/stomach deltas, untouched shared REAGENT, and full-stomach retention. It does not test client-side behavior (which cannot be simulated in this dedicated-server GameTest) or engine duplicate-callback suppression; the callback is invoked once at its due boundary as the engine's per-tick callback contract expects.

## Milestone 8: registered puddle interactions

- Dedicated GameTests place the actual registered `PUDDLE` block and block entity above a solid support, seed a real nonempty water source through `MS14Provider`, and use eligible server-level `Player` test doubles (the player entity type is explicitly checked against the eligibility tag).
- Empty-hand interaction uses the public Minecraft 1.21.1 `BlockState.useItemOn` followed by `BlockState.useWithoutItem`: `useItemOn` returns `PASS_TO_DEFAULT_BLOCK_INTERACTION` for the empty stack, and the test explicitly invokes the no-item callback only for that result. This verifies the block-state dispatch boundary and the protected `PuddleBlock.useWithoutItem` through its public wrapper; it does not call `ServerPlayerGameMode`/the network packet handler or simulate the client interaction.
- An eligible player click removes exactly 5 puddle water units, adds exactly 5 to STOMACH, and leaves shared REAGENT unchanged. Empty puddle and full stomach both return `PASS` and preserve their source/destination. A separate registered-bottle-on-puddle test calls the public `BlockState.useItemOn` path and proves five units transfer to the puddle without touching player STOMACH or shared REAGENT.
- Near capacity, source/destination quantities are admitted and split directly in integer cents; the prior floating-point candidate search is removed. Partial-cent requests/free space are no-ops, while any normally committed positive cent-sized admission conserves each reagent exactly. Registered interaction GameTests cover same-key 49.9/10.1 near capacity and proportional mixed-source admission. `MS14Provider` updates the two holders sequentially, so an exceptional failure between writes is not atomic. The isolated GameTest exercises block callbacks, not the physical hitbox/raycast path or full player packet dispatch.

## Integer-hundredths ingestion update

- Stomach ingestion alone uses `ReagentUnits` integer cents (SS14 FixedPoint2-style 0.01-unit precision). It checks conversion roundtrips and the 50-unit cap before provider updates, and only the stomach destination and metabolism activity are updated. Bottle, jug, and puddle all continue to use the same `StomachSystem.ingest` transaction; there are no source-specific admission exceptions.
- Tests cover 49.9/10.1 same-key conservation, half-full partial admission, two-reagent remainder assignment, a 49.999 legacy stomach (4,999 cents), zero/sub-cent quantities, overflow rejection, and repeated fractional requests. The 50-unit cap is exactly 5,000 cents and all stored stomach snapshots are checked against the cent representation.
- This ingestion update is one part of the broader cent-native reagent migration: `ReagentAttachment` and `ReagentComponent` now store authoritative integer hundredths, generic committed transfers, puddle gravity/flow, stomach-to-body transfer, and the metabolism core use cents for committed amounts. Float-shaped compatibility adapters and schema inputs remain at boundaries. Recipe/reaction and metabolite generation are not covered by any global conservation guarantee, and the two-holder provider commit is not exception-atomic; see the [fixed-point migration audit](2026-09-23-fixed-point-migration.md).

## Digestion behavior and boundaries

- Stomach contents run the digestion-only metabolism profile. The source is validated/bounded at 50 units, while generated metabolites route to the separately validated 1000-unit body reagent compartment. Shared-body processing remains separately scheduled first and deliberately excludes DIGESTION: milk (or any other digestion-stage reagent) injected directly into shared REAGENT is not digested; only stomach contents are.
- Product overflow is explicitly lossy: metabolism/effects still run, while `CapacityAddResult.excess` records products that could not fit. No excess is reassigned to blood, stomach, or a puddle.
- Stomach `Vomit` empties the full stomach solution, or the exact live stomach digestion transaction source (whose commit remains owned by `TickHooks`), before attempting a puddle spill. Unsupported/dead targets do not touch any compartment. Eligible targets receive -40 through initialized custom hunger/thirst owners, including when the stomach is empty; absent scalar state is not materialized. A status-capable living target receives `moonstation14:vomiting_slowdown`, a transient 0.5 movement-speed status for `ceil((80/6)*20) = 267` ticks. Status `UPDATE` takes the maximum remaining duration, so repeated vomiting refreshes without shortening a longer instance; the ordinary status lifecycle removes its movement modifier at expiry. Need-penalty projection failures are logged and produce `FAILED`, without rolling back the already emptied stomach or projecting transaction-owned changes backward. Failed puddle placement loses the already-emptied solution, matching upstream's ordering rather than claiming atomic egress. No shared-body or bloodstream contents are purged, and no synthetic `vomit` reagent is added. Bloodstream flush, forensics and the remaining anatomy behavior keep Vomit partial.
- Digestion `AdjustReagent` is explicitly skipped because its current handler uses living-body capacity and has no source-capacity-aware stomach semantics. There are currently no digestion `AdjustReagent` resources, so existing supported digestion effects are unchanged.
- Final detached body/stomach working copies and metabolism activity reconciliation run in `finally`; callback exceptions propagate after finalization. Invalid source or destination capacity is rejected before ordinary removal.
- Deterministic milk GameTests cover body-only non-digestion and staggered scheduling, plus stomach-only digestion at its due tick with one configured half-unit stage-rate removal, thirst effect scaled by actual removal/rate, no duplicate body processing, persistence, and continued activity enrollment for remaining stomach contents. Tick-level callback-exception persistence has no direct entity-level test seam yet; pure metabolism callback failures are unit-tested.
- Non-digestion reagent transfer remains routed to shared `REAGENT`; stomach ingestion is not a generic transfer rewrite or complete anatomy model. Bottle fill/spill, item/block interactions, and generic transfers remain untouched. Puddle contact is inert and does not consume reagents; gameplay exposure awaits real slip mechanics.

## Milestone 7: stomach-to-body non-digestion transfer

- During the existing 20-tick metabolism pass, after stomach digestion effects, `StomachDigestionTransfer` snapshots exact integer-cent quantities and routes up to 25 cents per eligible reagent at 0.5 efficacy to shared body `REAGENT`. Reagents with a DIGESTION entry and missing prototypes are skipped, so digestion-stage processing is not duplicated.
- Transfer is capacity-preflighted on detached copies using integer cents. Product body cents are `floor(source cents / 2)`: a 25-cent source transfer removes 25 cents and admits 12 body cents, with the remaining 13 cents the documented intentional upstream transfer inefficiency. Capacity-limited admission selects the maximum smaller source amount whose floored product fits (for example, 1 free body cent permits 3 source cents and 1 product cent). A full body retains the entire source quantity, and a source amount producing zero body cents remains as terminal stomach residue pending a wash/flush pathway. Destination admission is committed before source removal; no float delta or reverse-efficacy division participates in the transaction.
- Upstream raises `MetabolismExclusionEvent` for special blood reagents; MoonStation14 has no equivalent event/filter or blood-reagent classification. This transfer therefore does not claim to reproduce that exemption (including an ID-only `blood` guess).
- Body metabolism has already run when stomach routing occurs, so a transferred bloodstream reagent's effects are evaluated on the next scheduled metabolism tick, not the same one. This does not model anatomy, multiple organs, or separate bloodstream ownership.
- GameTest coverage uses sulfuric acid (bloodstream entry but no digestion entry): 1.0 stomach unit becomes 0.75 stomach and 0.12 body on the first pass, with the bloodstream effect deferred until the next pass at its actual 0.24-unit metabolism scale. Fixed-point unit tests cover exact cents, mixed/skip behavior, 1-cent free-capacity limiting, near-cap retention, and zero-product residue.
