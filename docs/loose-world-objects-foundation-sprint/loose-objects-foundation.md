# Loose-object foundation

`LooseItemEntity` is a distinct registered entity type that subclasses `ItemEntity`, retaining its stack/NBT storage API while intentionally not running vanilla `ItemEntity.tick` (merge, age despawn and player-touch pickup are therefore absent). Create with `LooseItemEntity.create(Level, Vec3, ItemStack)`; motion API is `launch(Vec3,float)` and `applyImpulse(Vec3)`. `settled()` and the rotation getter/setter expose current motion state. Profile IDs resolve through `LooseObjectProfile.resolve(ResourceLocation)`; unknown and absent IDs resolve to generic. Item NBT remains inherited and rotation/angular velocity/settled state are persisted.

Profile JSONs document mass, friction, restitution, throw tuning, geometry/render kind and impact-break capability. Runtime parsing/inheritance is not yet wired: current resolver uses the corresponding Java defaults for generic/jug/grenade. Generic profile defaults are deliberately small-object values; no entity collision shape or player pickup integration is provided. Grenade fuse/detonation and jug content spill/break behavior remain deferred to composition with their existing systems.

SS14 base item friction/restitution are represented as 0.2/0.3. SS14 throw speed 10 m/s is translated to 0.5 Minecraft blocks/tick using 20 ticks/s, with separate Minecraft-friendly spin; this is a 3D adaptation, not a direct 2D physics port. Tick fast-path skips settled objects, but moving objects still need simulation. Motion is server-authoritative; vanilla entity transforms synchronize position, with no client-side prediction/custom rendering yet.

Before each step, the destination block's chunk must already be present (`hasChunkAt`); otherwise the entity stops rather than requesting a chunk. This is a conservative boundary guard, not a swept-chunk or arbitrary-shape safe movement guarantee. Collisions currently use vanilla entity bounding-box `noCollision` and simple bounce damping, not SS14 fixture contact physics.
