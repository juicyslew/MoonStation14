# Radiation runtime slice

Source audit verified against SS14 checkout `c9df5ef5d675b0d1d226828bddf6b78c28502d91`:

- `Resources/Prototypes/Entities/Structures/Walls/walls.yml`: `BaseStructureWall` inherits `BaseStructure` and sets `RadiationBlocker.resistance: 2`; `WallSolid` and `WallPlastic` inherit through `BaseWall` (which inherits `BaseStructureWall`) and do not override the blocker. `WallPlasma` overrides to 5, `WallReinforced` to 5, uranium to 6, etc. The local typed `ConstructionEntityData` supports optional `radiationBlockerResistance`, resolved by the existing prototype runtime and consumed live by the radiation voxel traversal. Only local `wall_solid`/`wall_plastic` declare 2; there is no inferred shielding for unmapped blocks. The complete upstream catalog is not mapped locally.
- `Content.Server/Radiation/Systems/RadiationSystem.GridCast.cs` (`Irradiate`, `Gridcast`, `GetAdjustedRadiationIntensity`) confirms linear `intensity - slope * distance`, traversed blocker resistance subtraction, threshold behavior, and in-container blocker adjustment. `RadiationSystem.cs` confirms one-second source update cadence and source movement/enable lifecycle handling. The local clock anchors at the last processed tick, triggers every 20 game ticks, integrates no more than 20 ticks per call (lag catches up in bounded intervals), and resets without dosing on clock rollback.
- Upstream `RadiationSourceComponent`, receiver and blocker behavior is distance falloff, not inverse-square: intensity minus slope times 3D distance, capped at range 50 (or 50 for zero slope); losses are applied before the 0.1 minimum. This runtime applies one-second intervals, subtracts known wall losses, aggregates surviving source exposures, and then applies the minimum threshold. The Minecraft path uses loaded-cell 3D DDA; this is an adaptation and is not exact upstream entity/container geometry.
- Only the local `STEEL_WALL_BLOCK` and `PLASTIC_WALL` are explicitly mapped to the inherited resistance 2 from their local `wall_solid` / `wall_plastic` construction entity mapping. No generic opaque-block shielding is inferred; vanilla and other unmapped blocks are zero resistance. This is deliberately incomplete, not full wall parity. Container shielding and nonmapped upstream wall variants remain deferred.
- Source profiles are required provider-supplied resolved values; this slice defines no source catalog/default and does not register a reactor/singularity. A future singularity provider must supply its resolved source profile; reactor radiation is not functional yet. Living receivers exclude dead/removed entities, spectators, and parked player carriers; ordinary living entities and controlled physical bodies remain eligible. Damage is routed through canonical typed damage with the radiation cause.
- Feedback is an explicit Minecraft presentation adaptation: `damage_feedback/radiation` inherits `quiet`, so canonical damage still applies while no ordinary-hit flash, camera shake, timed-action interruption, or bespoke sound/art is implied. Upstream `Content.Shared/Damage/Systems/DamageableSystem.Events.cs` applies radiation as total rads with ordinary `ChangeDamage` (`ignoreResistances: false`, `interruptsDoAfters: false`); `DamageableComponent.cs` pain groups cover brute/burn, not radiation. Radiation taste/vomit thresholds in `Content.Shared/Mobs/Components/MobDamageableComponent.cs` are deferred and not represented by this feedback profile.

The source checkout revision and wall inheritance were verified locally. The broader upstream runtime semantics are documented as the verified slice contract; exact upstream behavior outside the mapped profile, occlusion, and cadence is not claimed.
