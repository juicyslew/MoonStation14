# Particle accelerator particle rendering

The upstream `ParticlesProjectile` prototype in `Resources/Prototypes/Entities/Structures/Power/Generation/PA/particles.yml` uses `particle.rsi`, unshaded, with visual states `particle0` through `particle3`. In pinned `RobustToolbox/Robust.Shared/Graphics/RSI/RsiDirection.cs`, enum values are South=0, North=1, East=2, West=3, and the source comment states these values match indices in the icons array. RSI loading packs each direction's frames direction-major. The local imported individual state sheets are 96×96: three 32px columns, with indices 0–7 occupying four directions × two frames and the ninth tile unused. Sampling index is `2 * direction + frame`; the two frames advance every two game ticks, following the 0.1-second RSI delay. The renderer uses half-texel inset UVs to avoid adjacent-tile bleed and samples the strength-specific resolved profile sprite stem.

Minecraft adaptation: the renderer chooses the nearest cardinal direction from projectile motion using positive Z as south; it retains the shared crossed-plane, no-cull fullbright billboard. This draws an animated sprite in the direction of travel without importing SS14's 2D sprite entity system. UV/frame math and actual resource dimensions are covered by `ParticleAcceleratorFrameUvTest`; this is not GPU render validation.
