# Recovery and cutover boundaries

WR10 does not activate, stop, install, publish or schedule anything. Until WR12 the legacy observer is the sole live owner. Cutover requires a fresh baseline, intake hold, explicit resolution/draining of active identities, correct SQLite backup including WAL, retained artifact evidence, and receipt-owned/hash-verified publication. Never disconnect required tools during active dispatch or run two schedulers. Unknown identity, cleanup or publication ownership means stop and preserve a scoped hold. The coordinator remains authoritative for lifecycle only after controlled WR12 cutover.

Terminal PASS/FAIL/ERROR results are immutable. ERROR recovery creates a linked generation on the same run, reuses still-valid evidence, and does not create an author revision or resubmit. Delivery repair never reruns checks. Rollback restores only currently hash-matching files owned by the publication receipt; it never rewinds database verdicts, replays validation, or resubmits authors. Provider pause cannot be inferred from HTTP reachability. See the indexed [coordinator guide](coordinator.md); the redesign's WR08 recovery record is a source-only reference, not an installed target. After installation, follow the installed documents and actual activated source.
