## Composition

- `AirAlarm -> BaseWallmountMachine -> BaseWallmountMetallic -> BaseWallmount`: anchored, non-colliding wallmount; inherited 100 W APC load and extension receiver. Relevant declared composition includes DeviceNetwork, DeviceList, AtmosAlarmable, AirAlarm and device-link source ports AirDanger/AirWarning/AirNormal. The alarm receives monitor reports; do not invent a local monitor merely because an alarm is mounted on a wall.
- `AirSensor -> AirSensorBase`; the abstract base has no parent and supplies AtmosDevice/AtmosMonitor and network defaults. Vents/scrubbers also inherit this monitoring composition. Keep monitor behavior reusable across actual composed owners.
- `Firelock -> BaseFirelock -> BaseStructure`: anchored static structure, Door, Firelock, Airtight, APC receiver, AtmosAlarmable and device networking. Standard firelock starts Open, bump opening disabled, click opening enabled. APC demand defaults to 5 W. Engineering access, welding/wiring and variant-specific composition must not be silently invented if the local runtime lacks a consumer.
- Local `GasType` supports all nine monitored gases, including Frezon. Existing resolved device composition, catalogs and family prototype merge strategies are the local data owners.

### Firelock prototype defaults (verified at pinned revision)

The supported local prototype chain now matches the source ownership boundary: `base_structure` contains only inheritance identity (local runtime has no typed representation for upstream Transform/Physics/Fixtures/Tag); supported firelock mechanics and defaults live on `base_firelock`, and the leaf `firelock` only overrides its device-network composition. In particular BaseFirelock's Door starts `Open` (so local `initiallyOpen=true`), with click opening enabled and bump opening disabled. `DoorComponent.DenyDuration` defaults to 0.45 seconds (`Content.Shared/Doors/Components/DoorComponent.cs`), while the source firelock explicitly sets that Door field and 15 Blunt crush damage in `Resources/Prototypes/Entities/Structures/Doors/Firelocks/firelock.yml`. Its `DoorStunTime` is the component default 2 seconds, and `SharedDoorSystem` computes effective crush stun as `DoorStunTime + OpenTimeOne` (2.1 seconds), not 2.4. Local source mapping is explicit: `door.crushStunSeconds=2.0`, plus `door.openTimeOneSeconds=0.1` at use.

`BaseFirelock` composes `PryUnpowered(pryModifier: 0.5)`, used as a speed denominator: hand pry takes twice the base time. `DoorComponent.PryTime` defaults to 1.5s and overrides the generic 5s pry time; FirelockLockedPryTimeModifier supplies the locked target multiplier 1.5. The local service consumes resolved `door.pryTimeSeconds` (default 1.5), applies the retained locked multiplier and divides by hand/tool speed. Consequently unlocked hand/crowbar durations are 60/30 ticks, locked 90/45 ticks at 20Hz.

Ordinary upstream `Airlock -> BaseStructure` also composes `PryUnpowered`, with the component default speed modifier 0.1. Standard `MobHuman -> BaseSpeciesMobOrganic -> BaseSpeciesMob` has no overriding `Prying` component. Thus an unpowered, unbolted airlock takes 15 seconds by hand or 1.5 seconds with the default crowbar. The local airlock prototype now represents this capability and the shared Door base time explicitly. Existing local bolt denial remains a departure: upstream applies a bolted duration multiplier, while this port still denies bolted prying. This change does not introduce powered hand prying or new bolt/wire behavior. ## Monitoring and alarm modes

Thresholds come from `Resources/Prototypes/Atmospherics/Thresholds/airalarms.yml`. `Content.Shared/Atmos/Monitor/AtmosAlarmThreshold.cs` tests inclusive Danger bounds first, then inclusive Warning bounds; no epsilon or added hysteresis. Temperature is kelvin, pressure kPa, gases mole fractions—not partial pressure.

| Threshold | Danger low/high | Warning low/high |
|---|---|---|
| stationTemperature | 193.15 / 393.15 K | low ×1.1 / high ×0.8 |
| stationPressure | 85 / 550 kPa | 89.25 / 385 kPa |
| stationOxygen | 0.10 / 0.30 | 0.15 / 0.24 |
| stationNitrogen | 0.10 / absent | 0.15 / absent |
| stationCO2 | absent / 0.006 | absent / 0.003 |
| stationPlasma | absent / 0.005 | absent / 0.0025 |
| stationTritium | absent / 0.004 | absent / 0.002 |

Resolve remaining threshold data from the pinned YAML, including water vapor, ammonia, nitrous oxide, Frezon's `danger` threshold and `ignore`; do not hardcode this abbreviated table as a second source of truth. A monitor chooses the highest severity across applicable measurements. Source gas ratios divide by total moles without an explicit zero guard; distinguish vacuum from an unavailable/provisional sample and document any adaptation. Real zero pressure independently trips the pressure threshold.

Air-alarm automatic mode: Danger selects **WideFiltering**, Normal/Warning select **Filtering**. Manual modes are Filtering, WideFiltering, Fill, Panic and None—not an invented Off mode. Relevant source presets: Filtering vents release toward one atmosphere; Fill vents use 50 atmospheres and pressure-lockout override; Panic disables vents. Scrubber Filtering/WideFiltering scrub the source filter gas set at 200 L/s (local 0.2 m³/s); WideFiltering adds WideNet. Fill disables scrubbers; Panic enables wide-net siphoning; None disables both. Match source pressure checks and supported local work/volume semantics before claiming preset parity.

Verified WideNet consumer behavior is center plus **four cardinal, air-connected neighbors**, not diagonals or a 3×3 square. Each included cell receives the full configured rate for the same elapsed interval; it is not one volume quota split across five cells. For Minecraft's 3D cells, use the horizontal cardinal plane around the existing foreground target as the explicit 2D-source mapping; adding vertical neighbors would be a separate adaptation. Check passable gas adjacency and operational ownership for each cell. Each individual transfer must conserve species/enthalpy and preserve pipe ownership. Electrical draw remains the device's existing receiver load, not another 5 W charge per cell. Scrubbing and siphoning stop at a 50-atmosphere pipe outlet.

**Fill consumer correction:** the preset requests 50 atmospheres (~5066 kPa), but `GasVentPumpComponent.FromAirAlarmData` assigns its `ExternalPressureBound` property, whose setter clamps to `MaxPressure`. That defaults to `Atmospherics.MaxOutputPressure = 4500 kPa` (`Content.Shared/Atmos/Atmospherics.cs`). Preserve the resulting **4500 kPa default effective bound**, rather than raising the port ceiling solely from the preset data. Earlier research's claim that 4500 necessarily truncates upstream behavior was incorrect. Fill still enables the actual under-pressure lockout override: ordinary release below the source 80 kPa lockout threshold leaks only `dt × (pipe pressure − room pressure) × 0.0001` moles, while the override permits the usual pressure-change calculation. It does not bypass the independent maximum-pressure guard. Match the setter/consumer behavior, not just the serialized preset.

Consumers: `Content.Server/Atmos/Monitor/Systems/{AtmosMonitoringSystem,AtmosAlarmableSystem,AirAlarmSystem,AirAlarmModes}.cs`, `AtmosDeviceNetwork.cs`, and `Content.Shared/Atmos/Piping/Unary/Components/{SharedVentPumpComponent,SharedVentScrubberComponent}.cs`.

## Network and lifecycle

Registration and device-list changes drive deregister/register/sync. Reports and alarm states carry source identity/tags; receivers filter tags and aggregate per-sender state by maximum severity. Automatic mode, network alarm severity and device-link High/Low ports are distinct consumers. Do not replace these with global room broadcasts or direct server calls from one alarm to a nearby shutter.

Power-down resets an alarmable receiver's cached alarm states to Normal; power-up synchronizes again. Monitoring devices stop sampling without power and retain their last monitor state for resynchronization. `ForceAlert` stores the receiver's own address in the same network-state cache; a power-down `Reset` therefore clears that forced state too. Do not add a separate forced-state field that survives power-down merely because the method comment says it persists until reset. IgnoreAlarms suppresses reception. Native grid/address semantics map to the existing local dimension-scoped transport and explicit loaded endpoint membership; this is an existing Minecraft adaptation, not permission to add another network.

Local freshness recovery distinguishes an **unknown/stale paid-power observation** from confirmed power-down. Graph invalidation can reject a queued packet before the next allocation solve without changing cached receiver power. Loaded receivers observe freshness before and after network draining, retain reports during uncertainty, and mark synchronization pending. Fresh full paid power requests the existing source Register/Sync and aggregate replay (air alarm), or RelaySync (firelock); pending intent clears on enqueue acceptance. This is lifecycle reconciliation, not guaranteed packet delivery or a new acknowledgment protocol. Confirmed power-down retains the upstream cache-reset behavior. Opening and alarm actuation still require fresh paid power; uncertainty never authorizes them.

Distinguish **monitor power loss/unavailability** from **receiver power loss**. `AtmosMonitoringSystem.OnPowerChangedEvent` only leaves processing on power loss and republishes its last alert on restoration; it does not send a safe/Normal report merely because sensing stopped. Likewise, unloading an explicitly linked source is not proof of destruction/replacement or a safe room. Preserve its last valid receiver report until a real update, explicit removal/reset or confirmed source-identity replacement, rather than pruning solely because a loaded-only resolver returns null. These lifecycle paths need direct owner-delegate/native coverage, not just classifier tests.

Local extension points: `DeviceNetworkRuntime`, `DeviceEndpoint`, `DevicePayload`/`AtmosDevicePayload`, `DeviceComponents`/`DeviceComposition`, and each endpoint's canonical DeviceList store. Existing alarm membership is currently vent/scrubber-specific; preserve one authoritative membership store when extending supported endpoint types.

### Receiver relay state and synchronization (verified at pinned revision)

`Content.Server/Atmos/Monitor/Systems/AtmosAlarmableSystem.cs` registers and calls `AtmosDeviceNetworkSystem.Sync` on power restoration; `SyncAlertsToNetwork` sends the complete `NetworkAlarmStates` map and the sender's actual `TagComponent.Tags`. `TryUpdateAlert` forwards that map only when the aggregate severity changes. `SyncAlerts` merges each source-keyed entry into the receiver map (it does not store the relay as one aggregate entry); `ResetAll` clears the receiver map. Power loss calls `Reset`, which clears cached reports. `AtmosAlarmableComponent.ReceiveOnly` defaults false and BaseFirelock does not set it, so Firelock is allowed to transmit sync requests/state. The local Firelock leaf's former `transmit:false` was an adaptation bug; it is now true and explicitly resolves the same AtmosMonitor transmit frequency used for receive. This frequency is required by the local typed transport's queued packet contract; the pinned upstream Firelock declares a receive frequency but leaves `TransmitFrequency` unset, so that is a deliberate Minecraft adaptation needed to make the audited power-up Sync call effective. Network ID, receive frequency and `requiresPower` remain resolved from the prototype.

Local relay messages preserve that state-map behavior: the payload's `source`/packet sender identifies the actual relay endpoint, its tags are checked against that endpoint's resolved `AtmosAlarmableData`, and `reports` carries the original per-source UUID/severity map. Receivers merge the original map through `AtmosAlarmReceiverState`, rather than caching the peer's aggregate as a new source. This avoids A↔B forwarding latching an old Danger after its originating source reports Normal. `RelayReset` models upstream ResetAll and clears the full receiver cache; for a monitor's individual `Reset` or explicit DeviceList member removal, the local `RelayRemove` adaptation removes only that original UUID so a different active Danger is retained. Receiver power-down fans out ResetAll while the alarm still has transmission authority. Firelock sync requests use the ordinary queued transport broadcast, but AirAlarm answers only when the requester is present in its canonical explicit membership. This is a bounded network request, not endpoint discovery or auto-pairing. Source unload remains absence, not a synthetic Normal/reset.

## Firelock safety: corrected call-chain behavior

- Powered Danger attempts emergency closure; powered Normal attempts opening only from exactly Closed; Warning does nothing. Normal reopening still traverses `TryOpen -> CanOpen -> BeforeDoorOpenedEvent`: a null-user automatic request **cannot bypass an environmental lock**. Do not interpret the alarm handler in isolation.
- `SharedFirelockSystem.OnBeforePry` cancels ordinary **powered** pry. Unpowered ordinary pry, strong pry and powered-tool pry pass this particular veto; welded/CanPry checks still apply independently. A successful pry in either direction starts a two-second emergency-close cooldown. Earlier research summaries inverted this condition; this paragraph supersedes them.
- Strong tool pry derives from composed `Prying`, not a crowbar-specific flag: `Resources/Prototypes/Entities/Objects/Tools/crowbars.yml` resolves `Crowbar -> BaseCrowbar -> BaseItem`; BaseCrowbar supplies `Prying` with default speed 1 and powered-pry false. `PryingSystem.TryPry` emits `StrongPry=true` for a tool with that component, versus false for bare hands. Local `FirelockPryService` derives the same capability from resolved `ToolProfile.prying()` for admission, timed revalidation and completion; inherited crowbars need no extra `strongPry` field. Bare-hand pry still requires known unpowered supply.
- Pressure/temperature warnings use strict differences **>20 kPa** / **>330 K**, not absolute thresholds. The periodic closed/welded/denying check updates warning/lock state; it does not itself auto-close an open door. Alarm Danger and the atmosphere solver's emergency pressure-stop path are separate closure triggers.
- The solver call is specifically `AtmosphereSystem.Monstermos.ExplosivelyDepressurize -> ConsiderFirelocks`, reached when equalization discovers Space with explosive depressurization enabled. It is not a generic “every unequal-pressure edge” callback. The source updates airtight/adjacency immediately after emergency closure and rechecks the edge before including it in the flood fill. Keep this distinct from the 20 kPa closed-door warning threshold.
- Local Space preflight departure: immediately before a `SPACE_FLOW`-eligible patch solve, inspect only its bounded, freshly validated finite patch cells for firelock lower controllers (upper cells normalize to the same root). This matches the upstream flood-fill's consideration of anchored firelocks on tiles traversed by the Space-connected patch, including a doorway cell that is itself finite; it does not search the world or close doors merely near an exterior edge. A successful immediate close aborts and requeues the stale patch so the next discovery rebuilds adjacency. Ordinary ambient/exterior patches do not invoke this hook.
- Ordinary opening requires power and an unlocked state, or a user access override for the environmental lock. Access override does not bypass power. Local access-system limitations need an explicit mapping; no new department-access framework is authorized here.
- Emergency closure only acts while Open and outside the pry cooldown. It uses ordinary close/partial-close handling; obstruction can abort/reopen, while successful collidability can apply the source crush behavior (15 Blunt). Do not implement an unconditional obstruction-ignoring slam.
- Shared close admission applies to ordinary closing **and** the partial-close boundary, not just emergency closing (`SharedDoorSystem.CanClose`, `OnPartialClose`; `DoorComponent.PerformCollisionCheck` defaults true). A body entering during ordinary phase one must not be unconditionally crushed instead of receiving that admission check. If an admitted close actually crushes, shared `Crush` schedules reopening after `DoorStunTime` rather than leaving the victim trapped. **Shared DTO correction:** existing local airlock resources and the firelock resource both store the base `DoorStunTime` (2 s) in `Door.crushStunSeconds`. Consumers add `openTimeOneSeconds` once for effective victim stun (firelock 2.1 s, ordinary airlock 2.4 s); reopening waits the base 2 s. The earlier note claiming this shared field already stored the effective value was incorrect.
- Do not copy ordinary airlock `canOpenOrClose` power gating wholesale: firelock's explicit power veto is on opening and its alarm handler. `EmergencyPressureStop` itself does not check power. Trace the shared close-admission chain when wiring the solver path rather than silently imposing an additional power condition.
- `Door.ChangeAirtight` couples gas blocking to collidability. Preserve that same relationship for both Minecraft doorway cells using the existing topology/invalidation owner. No parallel gas blocker or altered atmosphere solver is warranted.

References: `Content.Server/Doors/Systems/FirelockSystem.cs`; `Content.Shared/Doors/Systems/{SharedFirelockSystem,SharedDoorSystem}.cs`; `Content.Server/Doors/Systems/DoorSystem.cs`; `Content.Shared/Doors/Components/FirelockComponent.cs`; `Content.Server/Atmos/EntitySystems/AtmosphereSystem.Monstermos.cs`. ## Physical, asset and scope mapping

Standard firelock is the first variant. The approved R4 delivery supersedes the original dedicated-only assumption: an ordinary one-wide/two-high airlock can host an independently persisted `FirelockController` in the same cells. Standalone placement delegates to that same controller. Base and cover retain separate identities, states, paid power and network endpoints; either nonpassable door seals both cells. Cover motion never operates the base door. This composition adapts independent SS14 door entities to Minecraft's one-BE-per-cell constraint; no claim about a specific upstream map pair is implied. Glass and directional-edge variants remain outside this mapping. See `ASSETS.md` for the approved revision and targeting convention.

R4 rendering uses its exact approved frameless upper/lower leaves, travelling ±1 block, and one four-housing indicator component attached to the upper leaf. The base airlock is hidden only for rendering when the cover is authoritatively latched closed at q=0. Independent warning activation clocks, padded quarter-model-unit returns, shared authored selection geometry and inherited 0.6-second visual durations are distinct from physical 0.1/0.6-second stages. None changes base artwork or logical door state.

The pinned `Content.Server/Doors/Systems/FirelockSystem.cs` updates `DoorVisuals.ClosedLights`, `PressureWarning`, `TemperatureWarning`, and enables `PointLight` from pressure/fire while checking Closed/Welded/Denying doors; that 30-system-tick check does not gate warnings on power. `OnAtmosAlarm` separately checks power for alarm-driven door response. Accordingly local warning overlays/light remain visible for a latched-closed q=0 cover even when unpowered; open/moving covers remain dark per the authored R4 mask, and power remains authoritative for ordinary opening/alarm response. RSI `pressure_unlit` and `temperature_unlit` both specify `[0.8, 0.4]` delays, so their authored frames are 16 ticks then 8 ticks (24-tick cycle), not separate 16- and 8-tick alternations. The local planner now uses that shared frame phase with independent warning-start clocks. This is runtime presentation mapping only; no model, texture, or manifest approval is implied or changed.

Use the existing authored component-model/rigid translation approach for a vertical shutter, not vertex stretching or an invented model system. ## Local monitor implementation boundary (2026-10-29)

Upstream sensor-threshold editors exist only for standalone AirSensor devices; vent/scrubber monitor composition does not provide that UI. This authorized local scope extends monitoring on existing vents/scrubbers and does not claim standalone AirSensor UI or expose threshold editing in ventilation panels.

Vent/scrubber resolved data now carries `AtmosAlarmableData.sourceTags` separately from `DeviceComponents` link-port IDs; the air alarm carries the audited `syncWith` filter. Measurement reports are typed and queued through `DeviceNetworkRuntime`; an alarm accepts a report only from its exact live DeviceList identity and only when sender tags match resolved source composition and intersect receiver `syncWith`. Unknown/provisional samples are explicitly invalid and do not become Normal or clear the last valid source report. A committed `AtmosphereService.fireIntensity` hotspot at the monitored cell forces Danger when observed. Sampling is driven by the bounded `ATMOS_DEVICES` stage and the atmosphere cycle identity, gated by a fresh paid 5 W observation; the one-second APC billing solve is not the measurement cadence. Hotspot discovery is therefore observed at scheduler query cadence, not an immediate fire event. This is a Minecraft cadence adaptation, not immediate-event parity.

Runtime local atmosphere sampling uses `AtmosphereService.INSTANCE.sample(level, cell)` and existing foreground-cell targeting, not the presentation-only provisional fallback. Unknown ownership is not a physically safe reading. Existing physics/gas precision and cadence are retained; no float conversion, movement changes or simulation redesign is part of this sprint. The `ATMOS_DEVICES` stage uses the lifecycle-derived round-robin endpoint worklist, validates exact device identity, observes only fresh paid power, and limits work to its per-stage/deadline budget. It does not add a per-BE ticker or a world/network scan.
