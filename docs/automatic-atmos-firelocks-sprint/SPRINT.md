## Required behavior and acceptance

- Live gameplay consumes resolved typed prototypes, including inherited threshold and door defaults. Tests cover resolution, inheritance and actual runtime consumers—not data files alone.
- Monitor temperature/pressure and supported gas mole fractions using source-inclusive threshold boundaries. Unknown/provisional atmosphere observations must not be presented as physical sensor truth. Establish vacuum/non-finite behavior explicitly rather than inventing a source contract.
- Sensors and receivers obey fresh power, loaded endpoint identity, registration/membership and source-tag filters. Sender state aggregation, synchronization, reset and power transitions are tested; no global room broadcast or duplicate membership authority.
- Preserve upstream automatic mode selection: Danger selects WideFiltering; Normal/Warning select Filtering when automatic mode is enabled. Apply real supported device preset behavior through existing ventilation owners; do not equate Warning with firelock deployment.
- Powered firelocks respond to Danger and Normal according to upstream state/admission rules. Local pressure/temperature differential warnings and atmosphere-driven emergency closure remain distinct from alarm reception. Preserve obstruction, pry cooldown, ordinary interaction and power-loss semantics established by the source audit.
- Door passability, collision and atmospheric blocking transition consistently for both doorway cells. Closing/reopening must change actual finite-gas transport through the existing topology, just as normal doors do. No fixture-only or purely visual seal.
- Models, state indicators and sounds must be genuinely integrated and attributed. No stretched ordinary-door art, flat placeholder presented as finished, or checkpoint-only model delivery. Glass/edge variants are follow-up unless required for the standard implementation.
- Monitor readings in this sprint come from existing vent/scrubber composition. Upstream threshold editors belong to standalone AirSensor pages, not vent/scrubber pages; no standalone sensor block or vent/scrubber threshold editor is implied. Preserve resolved monitor defaults and show unavailable/cached readings distinctly.
- Existing airlocks, ventilation configuration, network configurators, power payment, hands/workspace routing and construction browser remain intact. Extend their shared owners rather than adding parallel render, networking, interaction or UI frameworks.
