# Prediction readiness contract

`prediction` selects `TimedInteractionPacketScheduleTest`, `TimedInteractionClockPolicyTest`, `HeldUseRequestDispatchTest`, and `BodyHandClientPolicyTest` from the one catalog in `build.gradle`. Report only the latency/delay cases asserted in those tests; the readiness report identifies scheduler and held-dispatch evidence. `BodyHandClientPolicyTest` covers the prediction-category client empty-hand retention policy: after a hand-query refresh it retains one 20-tick manual nomination, then consumes it only against a fresh reply matching body epoch, dimension, target face/block state, active-hand emptiness, and modifier context, with a fresh revision/sequence. Cancellation, competing actions, stale context/aim, and timeout invalidate it; DENIED is not automatically retried. A refresh barrier blocks only a pending QUERY without an action, avoiding the refresh/action race. Record outcomes in the current invocation report/log, not as a permanent contract or permanent pass count. This is JVM reconciliation/dispatch evidence, not live networking or authenticated server proof; a server harvest failure was not reproduced, so do not claim all failures definitively fixed. Keep authority, context-reset, transport-failure, and native boundaries explicit. No Minecraft process is needed for the focused task.
