# Connected prediction fixture

1. Launch normally into a fresh world; wait for the stock Sable six-substep bay.
2. Standing inside the stationary cabin, run `/ms14_connectedwall prediction start`. Do not press movement keys during its two scripted jumps. Use `/ms14_connectedwall prediction stop` to stop an unfinished capture.
3. Repeat while the cabin translates without rotation: `/ms14 shuttle_fixture motion <id> 0 0 2 0 30`, then start another capture. Keep the two reports for comparison.
4. Separately check walking/braking, boarding, wall contact, and another client's view. Include any jitter or penetration with the reports.

The fixture sends normal input intents; it does not move the body directly, launch clients, or introduce network delay.

The fixture samples production input and protocol evidence. Snapshot world and authority-projection coordinates are retained raw, but are not compared as a correctness oracle. Temporal coverage validates each restore anchor and its consecutive intervals independently per reconciliation generation; restored clocks may repeat across generations. Completed SDK-step IDs must match committed live intervals. Input sequence IDs are ordered but need not be consecutive and are not SDK timestamps. Selected and original launch-support poses require valid history-kind/source provenance; airborne native-frame absence does not remove the launch-support requirement.

Intervals carry actual before/after body world coordinates and the original launch-support frame pose (including while airborne). The collector transforms recorded points through each interval's own support pose and reports time-separated baseline drift, peak flight horizontal drift, landing offset, relative vertical range, frozen-air-reference variation, sample counts, duration, and excluded replay samples. Trajectory aggregation preserves append/observation order across all reconciliation generations, excludes replay intervals, and rejects duplicate live input sequences instead of silently choosing a record. Reconciliation discontinuities remain measurable. Nonzero horizontal input or unsupported/nonuniform/rotating frame motion is classified unsupported. No acceptance threshold is established: these measurements are diagnostic, not a movement PASS. The capture does not cover wall contact or observer presentation. A bounded JSON observation is written under `diagnostics/connected-prediction/`.
# Diagnostic report schema v3

The bounded client-only capture adds snapshot `frameStorage` (the optional frameState storage-space XYZ), immutable `lastPoseMatrix`/`logicalPoseMatrix` copied from the pose pair already used for authority projection, `rebaseRevision`, and `reconciliationStatus`. Snapshot arrival includes `arrivalClientTick` and `monotonicNanos`; sent intents and render samples include monotonic timestamps. `steps` records actual restored/completed SDK steps per reconciliation generation; `intervals` records selected-history provenance, frame pose, body endpoints/velocities, frozen air reference, and native collision-diagnostic availability. Render rows pair actual camera/body world positions with the original support pose and SDK step from the body's published presentation interval. `world` remains server snapshot XYZ; it is not the predicted body's frame-local point. `movementMode` does not attest support: use `onGround` and `frameStorage` independently; airborne frame observations need not identify a supporting frame.

Temporal and trajectory observations are collected only from production-selected step/interval/render data; the fixture does not implement a second predictor. Synthetic collector tests validate coverage and detect actual support-relative drift from synthetic world points; they are not runtime evidence. Wall contact and observer presentation require separate captures.

The reviewed epoch-2 capture showed takeoff/landing corrections with zero replay, while retained rendered frames were marked airborne: support-grounded inference cannot explain the visual delta. Evidence showed projected ground offset (-0.1597) then world-basis airborne correction (+0.1572 Z); landing correction was about -0.1385, with the second flight similarly +0.1341/-0.1242. These values motivate separating WORLD vs FRAME authority basis and arrival/render timing, not a gameplay correction; timing interpretation remains under investigation.
