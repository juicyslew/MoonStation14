# 2026-09-27 generic grounded Mob harness foundation

**Disposition: bounded generic grounded-body foundation delivered; not full possession or a live Mind-to-body control route.** SS14-like prototype data can select a supported host and provide typed movement policy inputs, while shared systems interpret those inputs. Villager and Pig fixtures exercise one common `Mob` path; the host mapping, policy construction, motor, ownership marker, lease, and world-step have no Pig-specific motor. This is the desired extension seam: after the shared actor-targeted control route exists, adding a supported species such as Pig should ordinarily be prototype/configuration work, not a new motor per species. It is not yet true that Pig is controllable by configuration alone, and data cannot implement behaviors for which no generic system exists.

## Source-derived foundation

- `CharacterData` (`src/main/java/com/juicyslew/moonstation14/component/codec/json/CharacterData.java`) carries strict optional typed `movement` data and `host_entity_types`, while retaining the existing `slip_data` field. The schema audit rejects malformed fields and requires movement configuration where host types are declared. This resembles SS14's data-driven prototype selection, but remains a narrower local schema: data declares supported identity and movement parameters; executable systems still implement behavior.
- `src/main/resources/data/moonstation14/moonstation14/character/human.json` configures grounded movement with walk/sprint speeds 2.5/4.5, acceleration 20, friction 20 with and without input, and hosts `minecraft:player` plus `minecraft:villager`. The player host remains transitional legacy enrollment; it does not establish that this new route replaces the carrier/legacy movement path.
- `src/main/resources/data/moonstation14/moonstation14/character/pig.json` configures grounded movement with walk/sprint speeds 4/4, acceleration 20, friction 20 with and without input, and host `minecraft:pig`. Its `slip_data` is a provisional local no-stun/no-slip choice, not established upstream SS14 Pig behavior. Pinned SS14 [Pig prototype](https://github.com/space-wizards/space-station-14/blob/c9df5ef5d675b0d1d226828bddf6b78c28502d91/Resources/Prototypes/Entities/Mobs/NPCs/animals.yml#L3592-L3661) inherits movement values from [`SimpleMobBase`](https://github.com/space-wizards/space-station-14/blob/c9df5ef5d675b0d1d226828bddf6b78c28502d91/Resources/Prototypes/Entities/Mobs/simplemob.yml#L1-L18) and [`base.yml`](https://github.com/space-wizards/space-station-14/blob/c9df5ef5d675b0d1d226828bddf6b78c28502d91/Resources/Prototypes/Entities/Mobs/base.yml#L42-L56), yielding 4/4; the pinned [`SharedMoverController.Input.cs`](https://github.com/space-wizards/space-station-14/blob/c9df5ef5d675b0d1d226828bddf6b78c28502d91/Content.Shared/Movement/Systems/SharedMoverController.Input.cs#L579-L603) routes input through the session's attached entity. These are reference evidence, not local behavior parity.
- `ModCharacters` rejects duplicate host claims across a catalog and provides a weak per-immutable-catalog host index. `CharacterIdentitySystem.enrollSupportedActor` maps configured host types for generic `Mob` and `ServerPlayer` actors: Villager/Human and Pig/PIG enroll; an unconfigured Cow remains unbound. Enrollment is not Mind ownership.
- `CharacterMovementPolicy.fromCharacterData` maps grounded movement data to the six numeric policy values and rejects unsupported/missing movement modes. It contains no Pig Java switch. `GroundedHarnessMotor(CharacterMovementPolicy)` wraps the same `CharacterMovementMotor` for either policy; there is no `PigMotor` or per-species motor. The former `HumanHarnessMotor` was removed.
- The prototype does not currently declare generic speech, hands, riding, swimming, or status capabilities. Speech and hands have no generic systems here; do not infer that Pig speech is mechanically disabled by its prototype. A capability field only has effect when a shared system consumes/enforces it. Riding and swimming remain unsupported, rather than species-configurable features.
- `MobMindHarnessOwnerMixin` supplies a synced false-by-default ownership flag on the `Mob` base. `LivingEntityMindHarnessTravelMixin` cancels vanilla travel on both sides only when that flag is true for a `Mob`; the inherited marker is false for the ghost, so it does not claim the ghost's travel. The Villager-specific owner mixin was removed.
- `GroundedHarnessLease(Mob)` accepts an explicitly configured candidate with the marker, bound identity/host, and grounded movement mode. It pauses AI and records/restores the prior `noAI` value on close. `GroundedHarnessWorldStep(Mob)` resolves the prototype policy, rejects passengers, and calls real `Entity.move` once. Real Villager and Pig lease/motion GameTests exercise the shared path; these are fixture-level proofs, not an actor-targeted runtime.
- Owned-Mob slip ordering is now bounded: `SlipSystem.onPuddleContact` defers the inline callback only for a `Mob` marked `MindControlledMob`; after publishing motor velocity, `GroundedHarnessWorldStep` calls `SlipSystem.onAcceptedHarnessMovement(Mob, actualDisplacement)` once. The accepted-movement callback uses post-motor velocity as its launch source and actor-local source latches. Unowned Mob and `ServerPlayer` slip paths remain unchanged. A configured leased Human Villager SpaceLube GameTest verifies a 20u launch survives the world-step; a separate unmarked Villager test verifies inline slip admission. This closes the previously reported “slip launch overwritten by world-step” risk for the tested route, but does not prove every lube-chain interaction or live control.

## Explicit limits and stop gates

- There is **no live Mind-to-Villager or Mind-to-Pig control**. `GhostControlNetworking` explicitly rejects CHARACTER Begin and Snapshot in the ghost-only client/server runtime. The carrier `ServerPlayer` HUMAN attachment persists. The candidate marker is currently a persistent server debug opt-in, not automatic possession merely because a mob prototype is configured.
- Speech and hands remain generic-system gaps; riding and swimming are unsupported. Unsupported movement modes fail closed.
- Do not claim “Pig mostly config-only” until one connected actor-targeted Mind controller/protocol/prediction/camera route demonstrably controls Villager and Pig using their configured values and the same runtime classes, with no species-specific Java additions; optional abilities must be enforced by generic systems; and Pig slip/stun semantics must be sourced rather than guessed. The old grounded `ServerPlayer` route is transitional and not retired.
- Remaining gates: prove the complete lube/slip chain beyond the focused launch-survival fixture; a motor failure after `Entity.move` still cannot safely retry; lease-close failures are now observable and retryable rather than silently swallowed, but failure-injection and connected lifecycle restoration are unproven; there is no live Mind actor-targeted state/client prediction or connected AI cleanup proof; and the carrier still has HUMAN attachment. Generic speech/hands systems and their capability data do not exist. Riding and swimming are unsupported. Pig's `no_slip` choice remains provisional, not upstream parity; no Pig slip test was run.
