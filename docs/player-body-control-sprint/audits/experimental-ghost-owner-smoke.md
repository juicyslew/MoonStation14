## Scope and safety

Test only one real, connected op-level-2 owner controlling the separate ghost Mob Harness. Do **not** test cross-dimension movement, teleport, respawn, higher permission roles, NPC/body transfer, or join-time behavior in this smoke. Do not change atmospherics configuration. `/ms14 mindghost start|stop` is registered for operators, but start refuses without changing ghost, Mind, or game mode unless the COMMON `experimentalMindGhostControl` gate was enabled when the server started. The command is unavailable to non-operators and start also intentionally refuses if the legacy `experimentalVerticalSliceMovement` gate is enabled; leave that legacy gate off. If the required config cannot be set safely, skip this smoke rather than enabling both experiments or weakening the gate.

Before testing, back up the test world and use matching rebuilt mod client and server. In the **correct running installation's** `config/moonstation14-common.toml`, set `experimentalMindGhostControl = true` and `experimentalVerticalSliceMovement = false`; both settings are required. Stop the server before editing and restart it so the startup gate samples the new value. Do not edit an atmospherics config. The repository's `run/config/moonstation14-common.toml` is a local, gitignored runtime config, not a versioned config template; other installations get the config-spec default (`experimentalMindGhostControl = false`) and must set their own active config. The gate cannot be hot-toggled: an active session persists until explicitly stopped or the server is stopped/restarted. Join with a real op-level-2 player in Survival or already-Spectator mode, recording which mode is in use. Keep a second spectator available only for checking ghost visibility.

## Owner procedure

1. Run `/ms14 mindghost start` once. Wait for the owner chat confirmation that the session committed. Check server INFO output for the matching Ready-handshake commit record (player, epoch, entity ID, ghost UUID) and first nonzero ghost displacement; correlate these to this owner/session. Command registration or a Begin message alone is not proof.
2. Confirm the camera follows the ghost. At a recorded high frame rate, remain stationary and make small, slow mouse movements; record yaw and pitch response and whether the ghost view jitters. Repeat with the owner's usual frame rate if useful. This specifically compares render-frame look behavior, separately from movement. Then press and hold Shift: it should descend the ghost while the camera remains bound to it, not switch to the `LocalPlayer` spectator camera. Confirm this directly: normal-feeling spectator flight or server displacement logs alone do not prove the camera stayed bound. Stop if Shift detaches the camera or look/camera presentation jitters.
3. If the camera stays bound, test WASD, strafe, sprint, and vertical input, recording movement jitter separately from stationary mouse-look jitter. Movement should feel immediate on the owner; observe for stutter, rewind/jitter, or unusual teleport while continuing to move and after input release. Check that release stops movement and recovery remains responsive. The client prediction is local to the owned ghost and reconciles to server snapshots; this smoke records behavior, it does not assert a latency/performance target. In third person, verify the visible proxy appears as expected, without treating visual presence as control proof. If safely available, optionally repeat a brief movement/stop observation with higher network latency and record the condition. Verify movement belongs to the ghost, not the `ServerPlayer` carrier. The `noPhysics` wall/fixture mismatch remains expected; do not treat passing through a wall as collision success.
4. Run `/ms14 mindghost stop`. Confirm the owner returns to the previously recorded game mode and expected camera/view is restored. If the starting mode was Spectator, confirm it remains Spectator.

## Abort conditions

Stop immediately on missing Begin/Commit, Shift detaching the camera, client crash or mixin injection failure, severe prediction jitter/rewind or unusual teleport, failure to restore mode/camera, unexpected UI, or disconnect. If movement freezes, issue `/ms14 mindghost stop`; if that does not recover safely, stop/restart the server with legacy movement left off. Do not repeat until the cause and recovery are understood. Preserve client/server logs and record precise behavior. Do not request NPC transfer, teleport, dimension change, or respawn. Spectator-clicking a mob is camera-only in vanilla and is not a supported possession test: it does not transfer the Mind or Mob Harness and does not grant movement.
