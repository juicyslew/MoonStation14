# 2026-09-29 airborne horizontal-speed diagnostic (pure motor)

**Scope:** `CharacterMovementMotorTest` exercises the current deterministic motor with decoded `human.json` and `pig.json` movement policies. It does not run Minecraft `Entity.move`, the server/client protocol, actual wall geometry, a connected world, or upstream SS14. The owner reported excessive speed around jumping into blocks and falling; these fixtures characterize a possible mechanism, not a diagnosis of that observation. No movement policy, prototype speed, or runtime behavior was changed.

At `dt = 0.05 s` (20 Hz), neutral surface and full fast-direction wish `+X`, human declares acceleration 20, walk 2.5, fast 4.5 blocks/s; pig declares acceleration 20, walk/fast 4.0 blocks/s. Both declare with/without-input friction 20/s and minimum friction speed 0.005 blocks/s. Motor acceleration is `min(acceleration * dt * wishSpeed, wishSpeed - velocity dot wishDirection)` when the latter is positive. This bounds the **projection**, not `hypot(vx, vz)`; airborne ticks have no ground friction. External impulse is added before acceleration. The tests explicitly assert the following (blocks/s unless noted):

| Pure-motor fixture | Human fast wish 4.5 | Pig fast wish 4.0 |
| --- | ---: | ---: |
| Airborne start `vz=3`, separate `+1 vz` impulse, `+X` wish: resulting `vx`, `vz` | 4.5, 4 | 4, 4 |
| Same tick horizontal resultant, displacement `(dx, dz)` blocks | `sqrt(36.25)` ≈ 6.021; `(0.225, 0.200)` | `sqrt(32)` ≈ 5.657; `(0.200, 0.200)` |
| Next airborne **no-input** tick, zero new impulse | same horizontal velocity | same horizontal velocity |
| Jump toward synthetic 1-block wall: `X` clipped on first two ticks; `vz=3` impulse on second airborne tick | `vx=0`, `vz=3` after second tick | same |
| Third jump tick clears fixture at `y=1.001336`; `vx`, `vz`, resultant | 4.5, 3, `sqrt(29.25)` ≈ 5.408 | 4, 3, 5.000 |
| No-input fall from `y=0.1`, `vy=-4`, `vx=fast`, `vz=3`: clipped floor landing tick | horizontal resultant 5.408; `dx=0.225`, `dz=0.150` | resultant 5.000; `dx=0.200`, `dz=0.150` |
| Next supported **no-input** tick, neutral surface | `vx=vz=0`, no additional horizontal displacement | same |

For the wall fixture, the jump's first displacement is 0.42 blocks, the second ends at 0.7532, and the third crosses the synthetic `y >= 1` clearance. The blocked `X` displacement zeros `vx` each obstructed tick; the unblocked `Z` impulse survives. This is an intentionally axis-selective resolver, **not** a Minecraft wall/collider implementation. On the landing tick the initial state is airborne, so ground friction does not run before the resolver reports ground; on the *following* tick the neutral-surface factor is `clamp(1 - 20 * 1 * 0.05, 0, 1) = 0`, since these speeds exceed 0.005. A non-neutral surface, smaller speed below threshold, external impulse, renewed wish, or different tick duration changes that result.

**Adapter/SS14 limits:** The server experimental player path injects 20 Hz, vanilla-derived gravity 32 blocks/s², jump 8.4 blocks/s, vertical drag 0.98, sampled surface factor, and `player.move(MoverType.SELF, …)` as the collision resolver; `Entity.move` may clip/step along different axes and has side effects absent here. Grounded harness movement uses a caller-supplied environment and the decoded prototype policy; the legacy direct-player experimental motor is hard-coded to HUMAN, so the pig numbers are **policy/motor measurements**, not proof of a live pig runtime trace. Network prediction, reconciliation, slip launch/contact, actual fall velocity and collision geometry can also affect perceived speed. The [pinned walk-intent decision](2026-09-29-ss14-walk-intent.md) makes default CHARACTER movement fast and Shift select walk (human 2.5/4.5; pig 4/4); it explicitly leaves airborne/collision speeds and SS14 policy/status multipliers unaudited. These results neither establish SS14 parity nor authorize a resultant-speed cap or any prototype adjustment. Owner-only connected retest and SS14 source comparison remain open before attributing the reported burst to this mechanism.
