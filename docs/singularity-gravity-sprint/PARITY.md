## Alignment and deliberate Minecraft adaptations

Aligned profile inputs include initial energy/level, radiation slope/intensity basis, energy thresholds and drain table, random-walk base speeds, event-horizon consumption cadence, and the source gravity base acceleration/range and stage-derived formulas. Thresholds are explicitly compared rather than assumed: local `levelForEnergy` uses the profile list and matches the pinned boundaries above. The local entity/consumer implementation is not the SS14 event-horizon/grid/collision system.

Deliberate differences for Minecraft feel and existing architecture: (1) a continuous shared movement force replaces SS14's `.5s` impulse; (2) force acceleration scales by configured multiplier `15` and horizon/level to retain a useful nominal capture force; (3) the effective query radius is `3*base` with a smooth ramp reaching full pull at `2*base`; (4) player lethal core is `min(.35*horizon,.35 blocks)`, while NPC/terrain horizon stays general radius; these are not upstream values. Existing lens, natural drain, random wander, and NPC/terrain horizon behavior are preserved. Minecraft's supported profile/runtime has no SS14 entity-component runtime: no unsupported component has been added to imitate `Physics`, `GravityWell`, or `EventHorizon`. PA is a separate system and `RadiationPulse` a separate effect, not components on this singularity; beacon attraction is also separate composition (beacon YAML and `SingularityAttractorSystem`), outside this profile criterion.
