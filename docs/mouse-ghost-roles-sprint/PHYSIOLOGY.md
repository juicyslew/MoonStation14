# Mouse physiology composition

The pinned SS14 checkout (`c9df5ef5d675b0d1d226828bddf6b78c28502d91`) composes `MobMouse` from `SimpleMobBase` and `BaseMobAnimal`. Local resolved composition maps this to `moonstation14:supported_simple_mob` → `moonstation14:supported_animal` → `moonstation14:mouse`; the hierarchy intentionally uses one chain because the local resolver has single-parent inheritance. `supported_simple_mob` provides shared Damageable/MobState/GhostOnMove, while `supported_animal` provides supported animal physiology/body defaults and metabolizer. Atmosphere exposure does not require a local `AtmosExposed` marker: subscribed `TickHooks` invokes `BodyTemperatureSystem.exposeOneSecond`, sampling world/contained atmosphere and applying thermal damage. `BarotraumaSystem` and `LungSystem` consume the resolved pressure/respiration policies. Live mouse validation remains pending.

The resolved mouse body starts with the existing `organ_lungs_pig` prototype. This reuses its generic local animal lung policy rather than duplicating an identical prototype under a new name; the `pig` asset name does not assert mouse-specific organ biology. Its local lung gas units/toxic-gas policy are an adaptation: `OrganData.Lung` uses the existing local gas-mixture and damage keys, not SS14 solution quantities. No mouse-specific upstream lung tuning exists. BaseMobAnimal also grants heart, stomach, liver, and kidneys upstream. Separate heart/liver/kidney organ mappings remain gaps. Mouse inherits local `StomachPrototypeComponent` enrollment consumed by `StomachSystem`; this represents supported digestive behavior, not the separate anatomy-specific upstream stomach organ. The local bases do not reproduce unsupported upstream components or the multiple-parent graph exactly.

Temperature mass is set to 12.566370614359172 kg from the upstream mouse collision fixture (circle radius 0.2, density 100: πr²ρ). This is an explicit mass approximation for local `TemperatureComponent`, not an upstream body-mass claim. Standard atmosphere values follow `MobAtmosStandard`; mouse temperature damage and respiration/barotrauma overrides follow MobMouse. No hands or humanoid profile are inferred.

Nutrition uses the existing typed Hunger/Thirst components, reducers, systems and HUD, not separate mouse-specific reducers. Mouse thresholds are 35/25/15/10/0, hunger base decay 0.5 and thirst base decay 0.04. Upstream `Content.Shared/Nutrition/EntitySystems/HungerSystem.cs:40–44` derives initial hunger from Peckish+10 to Okay, yielding 25 for mouse; thirst explicitly starts at 25. Initialization ranges are derived behavior, not extra upstream prototype fields. Hunger threshold classification is corrected to upstream's nearest upper threshold (`HungerSystem.cs:189–203`); this also changes Human status intervals, while its numeric defaults and base decay remain unchanged. Unit and focused native validation pass; see `VALIDATION.md` for limitations.

At the verified pin, HungerSystem and ThirstSystem independently apply 0.75 walk/sprint modifiers at Starving/Dead hunger and Parched/Dead thirst. They multiply to 0.5625 when both apply. Mouse does not configure optional `HungerComponent.starvationDamage`, and thirst has no direct health-damage rule. Reaching the nutrition threshold named Dead does not itself kill the mob. Jetpack-flight exemptions upstream do not imply a new mouse flight capability locally. Connected testing exposed that local native movement-attribute modifiers alone did not establish slowdown in the grounded harness motor; the controlled movement snapshot must carry the same nutrition factor to server movement and client prediction. See `VALIDATION.md` for current evidence.

Owner-requested handless self-ingestion reuses timed world-item/puddle ingestion, source transactions and stomach admission. `supported_animal` now composes the existing Mouth capability. Oral access checks the resolved Mouth plus absent/empty Hands composition; missing live hand state alone never qualifies a handed actor. World-item/puddle requests use exact body/epoch authority without a fabricated hand. Held ingestion remains hand-required. Future creatures must resolve their own mouth/stomach/body composition; no Mothroach entity or Mouse-specific eligibility switch is introduced. The world gesture is an explicit local extension, not verified upstream handless Mouse interaction parity; see `PARITY.md` and current validation status.

Mouse overrides vanilla `requiresCustomPersistence()` like the existing custom player-body harness. Minecraft's server calls `checkDespawn()` independently of NoAI; its native distance test follows physical players, not the controlled view. This override prevents station/controlled mice disappearing far from a stationary carrier while retaining normal chunk save/unload behavior. It is a Minecraft lifecycle adaptation, not a new physiology component or a change to movement/AI/collision values.
