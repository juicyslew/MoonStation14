# Crowbar / construction-step prying audit

Verified SS14 checkout revision: `c9df5ef5d675b0d1d226828bddf6b78c28502d91`.

Upstream source: `Resources/Prototypes/Entities/Objects/Tools/crowbars.yml`. The ordinary `Crowbar` inherits abstract `BaseCrowbar`, itself a `BaseItem` child. `BaseCrowbar` provides name/description, land sound, Crowbar tag, melee damage/MetalThud sound, `Tool` quality Prying and use sound, tile compatibility, steel composition, price, `Prying` component, Sprite/Clothing, and a Small Item; `Crowbar` overrides icon state and stored sprite. `BaseItem` defaults/composition are documented in `docs/construction-tools-parity.md` (including physical defaults deliberately not modeled locally).

Upstream consumers include construction interaction (`Content.Server/Construction/ConstructionSystem.Interactions.cs`), which uses PryingSystem, and many door/mech/lock interactions. This local addition intentionally models only the generic Prying tool quality for future construction-graph step requirements; it does not port `PryingComponent`, door prying, melee, clothing, physics, or other unsupported systems. The local `crowbar` tool prototype inherits `base_tool` defaults and resolves Prying at normal speed. `ModTools.canPryConstructionStep(catalog, toolPrototype)` is the intended resolved-prototype API for a construction-graph step consumer. No live graph consumer exists yet; do not claim prying steps are live.

The registered Minecraft item `ModItems.CROWBAR` maps by its registry id (`moonstation14:crowbar`) to the resolved local `construction_tool:crowbar` prototype. `ModTools.canPryConstructionStep(catalog, ItemStack)` performs this mapping and fails closed for empty/unregistered/unsupported items; it does not infer capability from item class or identifier alone. A flat model uses the existing `assets/moonstation14/textures/item/crowbar.png`. The player-visible item/catalog registration exists, but the actual construction graph consumer remains pending foundation/current-runtime integration; this audit does not claim prying graph steps are live.
