# Shared pipe-network contract

This records verified upstream behavior and the local implementation boundary; it is not an assertion of universal SS14 parity or sprint acceptance.

## Pinned SS14 behavior

At verified pin `c9df5ef5d675b0d1d226828bddf6b78c28502d91`, the prototype chain is `GasPipeManifold -> GasPipeSansLayers -> BaseItem`. `GasPipeSansLayers` provides inherited item, anchored Transform, damage/pipe-related composition and base item behavior; the manifold supplies six 50 L `PipeNode`s (`south0/1/2`, `north0/1/2`) at layers 0/1/2 and locked `AtmosPipeLayers`. `GasPipeManifoldComponent` defaults inlet names to south0/1/2 and outlet names to north0/1/2. `GasPipeManifoldSystem.OnCompInit` links every inlet to every outlet; `PipeNode.GetReachableNodes` yields `alwaysReachable` peers without a layer filter. All six therefore share one 300 L PipeNet mixture, not three isolated pairs. Local resolved manifold peers and 0.05 m³ port volumes are correct. Local layer IDs govern adjacency; they do not partition the manifold network. Sources: `Resources/Prototypes/Entities/Structures/Piping/Atmospherics/pipes.yml`; `Content.Server/Atmos/Piping/Components/GasPipeManifoldComponent.cs`; `Content.Server/Atmos/Piping/EntitySystems/GasPipeManifoldSystem.cs`; `Content.Server/NodeContainer/Nodes/PipeNode.cs`.

For a manual valve, `GasValveSystem.Set` invokes shared `Set`; open adds bidirectional inlet/outlet reachability, close removes it. Sources: `Content.Server/Atmos/Piping/Binary/EntitySystems/GasValveSystem.cs`, `Content.Shared/Atmos/Piping/Binary/Systems/SharedGasValveSystem.cs`, and `Resources/Prototypes/Entities/Structures/Piping/Atmospherics/binary.yml`.

## Local port contract and pending work

Local implementation: `PipeGasInventory` schema 2 is the authoritative `SavedData` image. Per-node metadata (identity/incarnation, volume, version, active status) and network membership are stored separately from each network's authoritative shared `GasMixture`; node shares are projections for sampling, not independently stored gas. `LoadedPipeComponent` discovers loaded physical connections; `LoadedPipeNetworks` caches topology, dirties/reconciles affected regions, and remaps only on invalidation. Unloaded nodes retain known membership and shared gas/volume: unload alone does not split a net. Unknown geometry during affected-network reconciliation blocks that network pending load/invalidation; no chunk forcing or invented connection is used, and unrelated networks remain available. Readiness gates captures/commits. `LoadedPipeGasWork` captures unique network mixtures; immutable proposals commit through server-thread `PipeGasTransaction` raw swaps with rollback before publication. Gas-only updates preserve membership metadata. Analyzer sampling scales network moles by `nodeVolume / networkVolume`, preserving temperature and pressure; TEG consumes network volume. World atmosphere remains a separate owner.

The manifold contributes 300 L to one shared network, plus any connected nodes' volumes. Valve open merges connectivity; close splits it on topology reconciliation. Passive gates transfer between separate nets and do not merge ownership. On node removal, nonempty retired-node shares are archived rather than discarded, avoiding silent local material loss where upstream deletion removes that node's proportional gas share. This is an intentional finite-world adaptation, not exact SS14 destruction parity. Schema 1 is incompatible: use a fresh disposable fixture world; there is no migration framework. Deleting only gas SavedData would leave stale block and fixture identities and is not a supported reset. Local six-face block representation and server-thread immutable transaction/rollback are Minecraft adaptations. Full SS14 anchoring/construction, break spills, analyzer presentation, and pipe chemistry are not claimed; upstream `PipeNet.React` runs pipe chemistry, which local pipe networks do not currently deliver.

Analyzer presentation deliberately retains the owner-approved named port/layer entries. Upstream `GasPipeManifoldSystem.OnAnalyzed` instead presents one combined 300 L manifold share; the local manifold presents six 50 L port shares to preserve that inspection interface. All six sample the same authoritative network, not separate inventories. Other nodes follow the generic upstream node-volume projection.

Existing approved TEG equations, R6, and 2J1000J1200 strict guards are unchanged and outside this contract. This record makes no claim of exact parity for unsupported systems, connected-client validation, feature-gate completion, or owner acceptance.

The existing synchronous loaded-discovery limit remains 384 nodes per component (inventory record limit: 65,536). Exceeding discovery coverage withholds the affected network rather than simulating independent sub-net inventories. This retained main-thread work bound is not an SS14 network-size rule or a measured large-network performance guarantee.
