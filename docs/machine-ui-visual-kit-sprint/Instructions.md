# Machine UI visual kit — historical scope and accepted outcome

**Status: owner accepted; implementation complete for the agreed visual-kit scope.** The original planning-only gate was cleared for a bounded client-side visual/interaction kit, **not** the generic device session-platform spike in [the deferred proposal](../device-ui-platform-sprint/proposal.md). Acceptance is the owner's scope decision, not SS14-exact parity, a green full GameTest suite, measured 20-player render performance, or verification of animation appearance and text clarity. See [completion](completion.md) for the decision and remaining debt and [implementation handoff](implementation-handoff.md) for implementation and test history.

## Original required outcomes (historical scope, not current blockers)

1. Bring the existing APC screen closer to upstream `Content.Client/Power/APC/UI/ApcMenu.xaml`: dark window chrome, sprite panel and two-column data grid, SS14-style switch, charge-dependent bar with percentage inside, truthful labels and divider/footer. The original static-prototype instruction was to use the already attributed static APC image, not claim a live entity view or animate it to suggest charge changes without fresh telemetry. Compare an actual connected Minecraft capture with an owner-provided SS14 APC screenshot rather than treating source comparison as visual acceptance. Retain unknown/unavailable external power and load, and show trip state accurately; do not fabricate SS14 telemetry.
2. Deliver reusable, **functional client-side** widgets for the major machine-UI element families surveyed in [the catalog](ss14-bound-ui-catalog.md), not merely APC-specific drawing helpers. Functional means real focus/input, layout, disabled states, clipping and model-to-view updates for client-owned interactions; it does **not** authorize server-side chemistry, orders, item movement or device contracts. Gate widgets needing authoritative owners, especially inventory transfer. See [architecture](architecture.md) and [milestones](milestones.md).

The target was Minecraft **1.21.1**, NeoForge **21.1.224**. Client classes stay on the client and must not load on a dedicated server. Style/layout, widget state, and `ApcMenuService`/`ApcMenu`/APC packets remain separate; `PowerDeviceBlockEntity` stays authoritative. Ordinary authenticated `ServerPlayer` menu transport is not MobHarness/possessed-body action access. This scope authorized no generic server menu framework, new machine simulation, upstream XAML/C# copying, project-wide instructions or unrelated sprint changes. See [visual parity](../apc-machine-ui-sprint/visual-parity.md), [APC handoff](../apc-machine-ui-sprint/current-handoff.md), [catalog](ss14-bound-ui-catalog.md), [architecture](architecture.md), [milestones](milestones.md) and [assets plan](assets-and-attribution-plan.md) for the original boundaries.

## Subsequent authorized delivery and evidence

The earlier **static image only / no animation** rule described the initial prototype, not a permanent ban. A later owner-authorized import added four original **CC-BY-SA-3.0** APC sheets with adjacent license notices and attribution; [animation asset provenance](apc-animation-assets.md) records source, rights and hashes. The fixed south-facing 2D GUI preview selects layered FULL/CHARGING/LACK animation from authoritative visual state; **UNKNOWN falls back to the attributed static image**. This is neither a live entity preview nor a license to infer numeric load or external-power telemetry. Breaker, revision, charge, trip and visual state are synchronized; numeric external supply and load remain unavailable, not invented.

The owner reported two-real-client switch updates and an overload trip, and confirmed title dragging, resize re-centering, one server-only breaker sound and a functional client-only gallery. Those are bounded observations, not proof of every connected-client lifecycle, accessibility or visual-parity path; see [owner feedback](owner-feedback-and-next-slice.md). The owner explicitly requested, then waived, an immediate manual check of the new reusable APC animation and text contrast, accepting the visual risk **without verifying** animation appearance, UNKNOWN fallback, gallery visual fixes or text clarity. The latest isolated 171-test GameTest run had one failure; the full suite is not green, and 20-player render timing and allocations remain unmeasured. Follow-up telemetry, new server owners/actions, other machinery, visual retests and performance claims require their own evidence and authorization; see [completion](completion.md) and [implementation handoff](implementation-handoff.md).
