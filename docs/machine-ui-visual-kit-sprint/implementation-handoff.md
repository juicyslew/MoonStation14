## Current technical boundary

- The existing APC already predicts breaker presentation locally while the server remains authoritative; a prediction is not a confirmed breaker change. Its menu/session/revision checks and `PowerDeviceBlockEntity` ownership remain the authority boundary. Do not treat normal authenticated `ServerPlayer` menu transport as MobHarness action access.
- `ApcMenu` adds an initial snapshot readiness marker and committed client breaker/revision/trip snapshot to avoid exposing partial menu-slot updates. `ApcScreen` gates switch input until the initial snapshot, handles pending response/timeout and fresh-snapshot recovery, and uses client-only window/switch rendering. Automated coverage does not prove connected-client behavior, including initial revision zero, later updates and second-viewer presentation.
- Reusable client-side pieces under `ms14/ui/` include window chrome/geometry, switch and meter math, tabs, search list, draft field, slot grid, queue and sample viewport widgets; bounded list, field, option, queue, slot-grid and viewport models support them. These are client interactions/fixtures, not connected machine implementations. Missing authoritative inventory/chemistry/cargo/lathe/etc. owners and intents remain gated: no real item transfer, orders or invented telemetry.
- There is no new server tick or render loop for this kit. Client-only collection models cap entries at 512; `MachineSearchList` limits a page to at most 24 row draws and caches labels/tooltips on snapshot changes rather than reconstructing them per draw. These are design bounds, **not** measured 20-player render timing or allocations.
- `ApcScreen` now uses the authoritative visual state to select layered base + FULL/CHARGING/LACK sprite animations in a fixed south-facing GUI preview; UNKNOWN retains the existing attributed static APC PNG fallback. The attributed animation PNGs and byte hashes are recorded in [APC animation asset provenance](apc-animation-assets.md). Reusable sprite animation models support bounded 1–8 directions; this is not a 3D model or a live entity preview. The owner waived immediate manual animation checks; appearance is not empirically verified, and preview render cost is unmeasured. Numeric load and external power remain unavailable rather than fabricated. The owner confirmed title dragging, resize re-centering and one server-only breaker sound after the UI-click suppression fix; audible network latency remains, and no audio prediction is claimed.
- The owner reported two-real-client switch updates and trip and identified SS14/MS14 screenshot files; see [owner feedback and next slice](owner-feedback-and-next-slice.md). The initial switch/trip/close observations predate the fixes; later title-drag, resize and audio checks remain bounded feedback, not proof of every lifecycle/accessibility path.
- `/ms14_ui_gallery` is an opt-in client-only demo under `client/gallery` with no server actions; see [manual gallery](manual-gallery.md). The owner tested it and reported it functional. Subsequent custom-text/search-row fixes and text contrast have not been visually retested; the owner accepted the risk without empirical verification. It does not validate connected machine behavior.
