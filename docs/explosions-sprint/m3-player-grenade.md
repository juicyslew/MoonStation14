# M3 — player grenade implementation

## Status

**Implementation sprint owner-designated complete.** Automated behavior is verified, but owner connected-client acceptance and balance approval are not. This is a greenfield project with no production server and no save migration. The intentionally destructive player-grenade path is part of current scope; claims/world-protection and operator/disposable-world gates are not current requirements. Revisit protection if multiplayer/claims are introduced.

The grenade is a single fixed disposable item. Modular construction is deferred. SS14 reference facts are pinned in [the proposal](player-grenade-proposal.md): prime on use; throw separately; fuse three seconds/60 ticks; beeps on tick 0 and tick 40; expiry at tick 60; `ExGrenade` source `Explosive` is 120/3/10. Local registered/server-resolved `moonstation14:ex_grenade` data at `data/moonstation14/moonstation14/explosive_source/ex_grenade.json` is currently provisional 380/3/10 and selects `explosion_type: default`; unresolved source IDs fail closed. This is not parity or validated balance. Local `moonstation14:default` at `data/moonstation14/moonstation14/explosion/default.json` carries damage/break metadata and `temperature_kelvin: 800`, but no gas hotspot/heat deposition/fire-stack effect is implemented. SS14 `Default` itself has no `fireStacks`; that is distinct from `FireBomb`'s `fireStacks: 2`.

## Current behavior and boundaries

- Temporary configurable keys: **N** = PRIME and **M** = THROW. These are temporary pending a future context-aware input system (e.g. E/Z/left-click). Generic throw after the hands/inventory/interactions sprints and generic item use/throw dispatch are explicitly out of scope.
- There is no generic item-use/throw dispatcher. Player actions are controlled-body actions authorized through `LIVE_HANDS`; vanilla carrier and `JugItem.use` are forbidden. Prime the grenade while it is in the active body hand. Throwing is separate, transfers the armed item, and preserves its deadline. Server-authoritative wall/floor impacts have damped bounce/slide/friction; impact neither detonates nor resets the 60-tick fuse, and only fuse expiry blasts. Holding it through expiry detonates in hand. If the grenade's block position is occupied, the trusted origin resolver uses an adjacent loaded AIR voxel as the blast origin; it does not move the grenade entity or load chunks.
- The creative-tab item model references actual vanilla `minecraft:block/cocoa_stage2` geometry in `assets/moonstation14/models/item/grenade.json`; its hand display transforms render the pod in-hand and raised ground transform lifts it visually from the ground. The thrown renderer remains vanilla `ThrownItemRenderer`, and server physics are unchanged. Registered, attributed SS14 `beep1.ogg` sounds on PRIME at 0 and +40 ticks, while `explosion1.ogg` sounds when the blast is applied, matching the exact prebuilt `ExGrenade` three-second/two-beep cadence. Both fixed sound events use packet radius 32 and per-sample `attenuation_distance: 32` in `sounds.json`; call-site gains are 0.35 (beep) and 0.5 (explosion), with pitch unchanged. Original SS14 `beep1.ogg` and `explosion1.ogg` are unchanged MONO samples; original SS14 `explosionfar.ogg` is an unchanged STEREO sample imported with its CC-BY-SA-3.0 notice retained. For applied/partial blasts, same-dimension real players selected server-side with `getCamera()` receive exactly one mode: positional near audio at <=32, or far audio in (32,96). Far plays locally at the camera with bounded gain <=0.25 tapered toward zero at 96; this is not a global broadcast. Carrier/camera movement and OpenAL perception remain unverified in a connected client. This differs from modular/configurable `TimerTrigger`, which defaults to five seconds, one-second beep intervals, and `general_beep.ogg` ([pinned prototype](https://github.com/space-wizards/space-station-14/blob/c9df5ef5d675b0d1d226828bddf6b78c28502d91/Resources/Prototypes/Entities/Objects/Devices/Electronics/triggers.yml#L12-L38); [component](https://github.com/space-wizards/space-station-14/blob/c9df5ef5d675b0d1d226828bddf6b78c28502d91/Content.Shared/Trigger/Components/TimerTriggerComponent.cs#L74)). After an applied/partial blast, bounded brief vanilla particles `EXPLOSION` 1, `FLAME` 16, `LARGE_SMOKE` 12 are emitted. This is a local Minecraft translation, not SS14's `Default` tile-based `fire.rsi` overlay/light/camera shake ([pinned explosion prototype](https://github.com/space-wizards/space-station-14/blob/c9df5ef5d675b0d1d226828bddf6b78c28502d91/Resources/Prototypes/explosion.yml#L11-L13); [client overlay](https://github.com/space-wizards/space-station-14/blob/c9df5ef5d675b0d1d226828bddf6b78c28502d91/Content.Client/Explosion/ExplosionOverlay.cs#L103-L119)). The throwable throw sound remains a vanilla placeholder. Retain the adjacent license notice; see [grenade audio attribution](grenade-audio-attribution.md).
- A retained M press during PRIME result/full snapshot refresh is handled; server strict token/revision checks remain unchanged. Timer beeps do not change ownership revision.
- The capped blast classifies ordinary non-air blocks with nonnegative destroy speed at fixed local tolerance 2, including dirt, grass, stone, chests, torches, rails, plants, and station floors/walls/ceilings. Negative-hardness blocks and explicit admin/special blocks (bedrock, barriers, command/structure blocks, portals, etc.) remain protected. It never loads chunks; planner safety `MAX_VISITED=256` is a hardcoded implementation bound (not an SS14 prototype value), still bounded. Local tolerance 2 is likewise a hardcoded planner choice. setBlock-to-AIR may delete block-entity/container contents; no drops are guaranteed. There is no generic config/operator/dimension gate.
- No chunk loading to finish an explosion. The held fuse service only advances for a connected authoritative living controlled body; disconnected/dead-body held timers therefore pause/stop ticking as currently implemented. Offline expiry/restart semantics are not promised.

## Known risks / follow-up

- Numeric local grenade values (380/3/10, tolerance 2) are provisional and not calibrated for Minecraft 3D; the SS14 reference remains 120/3/10. Do not represent this as SS14 parity or approved/validated balance.
- setBlock-to-AIR may delete block-entity/container contents; no drops are guaranteed.
- The input bindings are temporary and are not a general interaction design. The actual vanilla cocoa pod model is an interim item model, not a custom grenade asset; its hand/resting presentation still needs connected-client verification.
- Held fuse progress is contingent on the connected living authoritative body, and there is no stated offline/disconnected expiry guarantee.
- Client animation/interpolation and connected-client behavior remain untested. Record an owner-connected-client run before claiming client acceptance; continue to defer modular grenades and generic throw/use dispatch.
