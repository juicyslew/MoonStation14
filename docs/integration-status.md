# Integration status board

Run `./integration-status.ps1` to render and open the read-only board at `work/agent_exchange/integration-status.html`. Use `-NoOpen` to render without launching a browser. The responsive board has three columns: **Validation actively running**, **Ready for owner**, and **Other states**. Only `owner_attention.collect(...).awaiting_owner` supplies active owner review cards; old technical passes or prior manual-review history cannot recreate one. Ordinary owner feedback is reconciled by the observer and removes the review card automatically; there is no manual clear or sign-off action on this board. Give feedback to the agent in the normal conversation. A technical pass is not owner acceptance.

The board does not contact OpenCode, dispatch gates, or make decisions. Its owner-feedback observer's `owner-feedback-observer.json` reports observation health; stale/unavailable observation and its errors are visible, never a verified empty queue. Candidate-bound sidecars under `progress/` are informational; only the candidate receipt's persisted gate outcome is a verdict. Operational gate health is separately bound by candidate ID, snapshot key, and the registered `gate_request.session_id` in `gate-health/<candidate_id>.json`; it is never a technical verdict. Accepted health states are `observing`, `active`, `recovering`, `blocked`, `api_unavailable`, `superseded`, and `finished`. `checked_at` records polling only: `observing` (no current execution proof) and `api_unavailable` remain unconfirmed even when polls are fresh. For validation, a row is active only when its candidate/snapshot-bound progress is `running`, it contains a live runner PID plus the current check index, argv, and log; queued mutex waiters are always in Other states. Model review is not test validation. `active` gate health counts as verified only with recent bound `last_activity` or the core's bound live-runner proof; polling cannot refresh activity age. Recovering shows the same-lead resume state without claiming execution proof. Other nonterminal work without fresh verified activity is unconfirmed/stalled after 90 seconds; duration alone never fails an actually live lead. `admitted` means only dispatched/admitted, not awaiting owner review. Owner disposition and author-completion delivery remain distinct.

Progress updates preserve `stage_started_at` while the phase is unchanged. Heartbeats must not rewrite command arguments, log paths, runner/child PIDs, or real-check evidence; only actual phase/check transitions update those fields. Old superseded requests are not current queue heads; owner attention selection remains owned by `owner_attention.current_work`.
