# Player ventilation test (experimental, not acceptance)

**Prefer the ready-made [finite ventilation fixture](ventilation-demonstration-fixture.md)** for gas-flow testing. It supplies sealed rooms, finite initial gas, connected pipes, real power, pre-paired devices and room/pipe readings in an existing test world. The steps below are for testing hand installation separately, not prerequisites for the fixture.

1. In a **new or disposable test world**, enable server `enableAtmospherics=true` before starting the server/world; it is sampled at server startup and defaults to false. Do not use the generated station as the test room: its entrance is open. Build a small, fully sealed finite room with room-side air in front of both devices (a closed 6×6×4 interior is within the current 1024-probe endpoint bound). The old 384-probe endpoint limit is superseded; an open doorway still fails regardless of size.
2. Before controlling the character, use an unparked Creative player to prepare the powered source/substation/APC graph and APC cable nodes at the planned machine locations. Cable spools still use ordinary player `useOn`; the temporary body B route does not install them. Take **Gas Vent**, **Gas Scrubber**, **Gas Pipe Segment (Primary)** and **Air Alarm** from **Moonstation Items**. Drop these functional items; control a character, pick them up with **G**, and select the intended active body hand with **V**. Creative-carrier use does not install them. The separate `gas_pipe_visual` fixture is cosmetic, not a gas pipe.
3. Aim at a reachable support face with adjacent air and press **B** with the installer in the active body hand. Vents, scrubbers and alarms support walls, floors and ceilings; the fixture front must point away from the support. The pipe connects immediately **behind** the device. For concealed piping, use **Shift+B on a Steel Wall** with a Primary Gas Pipe Segment: expect a chat receipt and an unchanged solid wall. Then mount the device on that face. With an empty active hand, aim at the alarm and press **B** to open it. Direct device menus should not open. Break an exposed functional pipe in Creative and verify the same spot accepts a new segment.
4. Extend wiring from the **existing powered station APC**. Put connected APC-tier cable nodes within **3 blocks** of each device and alarm. Wait a second, then open the alarm: it should remain open while the body stays in reach with clear sight, without continuous aim. Use **Devices → Refresh → select → Pair → Configure**. The detail names the device; use **Controls** for enable/mode/pressure/rate, **Filters** for scrubber gases, and **Back to Devices** to choose another. Check your GUI scale. The alarm needs **100 W**, each device **5 W**; no data cable is needed. Manual APC recreation remains deferred.
5. Via the **alarm**, leave the scrubber enabled in **FILTER** mode with **CO2** selected; its default filter list includes CO2. Start with an empty/vacuum pipe and room air containing measurable CO2. For test setup only, a Creative CO2 producer from the Blocks tab can face into the sealed room; remove it and restore the solid wall before measuring finite capture so it is not a continuing gas source. If the room has no CO2, capture cannot be observed. The alarm exposes vent external pressure in kPa and scrubber rate in m³/s with Apply buttons; direction and pressure-check selection remain absent. First observe capture into finite connected pipe storage. An empty supply pipe cannot release gas merely because a vent is enabled. To test release, route gas-bearing storage to a vent facing a **separate sealed low-pressure room**; one vent and scrubber in the same room will not demonstrate room-to-room transfer.
6. Measure **room air** before/after with an ordinary Creative observer using the atmosphere analyzer (or a second observer), not the pipe or solid wall. The analyzer's vanilla item-use path is not wired to the temporary body B action; do not assume that merely holding it in the character's hand produces a reading. Compare room CO2/pressure over several completed intervals; toggle the APC/breaker to check that transfer stops without paid power and alarm access stops without its full 100 W. Analyzer readings alone do not prove the complete pipe conservation ledger.

If **B** reports denial or nothing moves, distinguish `NO_CHANGE` (alarm menu opened) from placement. Check exact active hand/item, body control, reach, loaded clicked face and adjacent air, wall face/sturdiness for alarm mounting, and that the target is not occupied by the character body or another collision. Check that **every opening is closed**, both device fronts see finite room air, primary ports join behind the devices, each receiver has a known APC-tier cable node in its local 3-block Euclidean reach on a powered graph with unambiguous attribution, the alarm receives all 100 W, devices are loaded and explicitly paired in the alarm, settings are enabled, sufficient device power has completed a 20-tick interval, and the pipe contains gas/capacity for the intended direction. Offline links may remain listed but cannot be edited as online devices. The current alarm flow does not provide general DeviceNetwork/access behavior, automatic modes, alerts, directional-bound selection, or wide-network association. An open or unloaded room endpoint is not an eligible finite room. Crash containment limits the effect of failures; it does **not** fix a body-collision denial. This is a manual procedure to try, **not** a client-verified success claim or a save/restart/crash-atomicity guarantee.

Future generated-station sealing is an owner decision for **new worlds only**: closable door/airlocks, no retrofit. The existing station entrance remains open; its potential 6×6×4 endpoint eligibility after sealing does not mean doors/airlocks, wiring, or gas seeding have been implemented.
