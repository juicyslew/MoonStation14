# M0 audit: network power, finite gas, and scanner query

**Status: research only. No production feature is authorized or implemented by this audit.**

This audit records viable seams and unresolved contracts for powered ventilation. Pipe placement is authorized only for the controlled body (never arbitrary client-selected body/position). Scanner cable visibility is explicitly **presentation-only**: ordinary `CableVisualServerHooks` snapshots disclose cable coordinates to modified clients. No anti-cheat, secrecy, or confidentiality promise is made.

## Local seams and blocks

- `PowerRuntime` and `PowerLiveLoop` already separate deterministic allocation from live device discovery and operate in discrete ticks. `PowerLiveLoop` currently models lamp loads as fixed kind demands, groups them on APC networks, allocates available inputs plus bounded battery discharge, and adjusts battery joules using elapsed seconds (`elapsedTicks / TICKS_PER_SECOND`) at solver invocation. This is not a 20-tick billing boundary: a future powered device needs an explicit registered demand, actual-delivery attribution, and exactly-once interval accounting that respects the live loop's invocation cadence. Do not charge on each atmos callback or infer a periodic 20-tick interval without changing/confirming scheduler semantics. Live device reconciliation must not debit twice or use stale topology after cable edits.
- Cable storage is server-owned topology and supports change/watch synchronization. `CableStorage.get` and `has` are not strictly read-only: they can prune stale host records, marking chunks dirty and notifying visual/graph listeners. A scanner query must avoid those mutating accessors or explicitly accept and isolate cleanup; use a truly non-mutating loaded-data read path for presentation querying. Chunk visual snapshots are not a privacy boundary: `CableVisualServerHooks` transmits records to watchers, and client occlusion only changes presentation. Keep that behavior unchanged for this scope.
- Atmosphere service, mixture, and reaction code already owns gas quantities and thermal/reaction evolution. `AtmosphereService` exposes read sampling and mutation APIs such as `addGas`; atmosphere update/reaction paths also mutate persisted finite-cell data. A future finite pipe network must transfer through those gas semantics rather than invent a second gas representation. Network topology split/rejoin, chunk unload/reload ownership, and atomic multi-edge transfer have to be specified before implementing finite storage; a visual pipe map or per-tick independent edge copy is not sufficient.
- Vent/scrubber device behavior must be split into network interaction and device control. Scrubber output must go to explicit finite waste storage (or an explicitly accepted sink), not disappear. Vent delivery must debit the same authoritative store exactly once.
- Scanner should query server-owned cable records and an atmos-approved pipe index without mutation or force-loading. Selection must use controlled-body world position and a bounded 3D sphere; send bounded observer-targeted deltas, not shared world/chunk state. The selected scanner cable concealment is presentation-only; scanner packets improve presentation for that observer only and do not remedy the ordinary cable snapshot disclosure. Placement is controlled-body-only, never arbitrary client-selected body/position.

## Recommended models (not settled)

**POWER CONTRACT UNRESOLVED:** bill energy from power allocation, not per atmos update. The current `PowerLiveLoop` invocation accepts elapsed ticks and uses them to prorate battery energy; it does not establish a 20-tick allocation boundary or generic device-load metering. Confirm the live scheduler cadence and add demand/served-watt attribution before settling a billing interval. Owners must decide whether the meter charges actual served demand, requested demand, or fixed draw, plus partial service, topology changes, and rounding/remainder conservation. Do not charge a full interval repeatedly.

**RECOMMENDED finite gas persistence:** network stores own a conserved gas mixture per connected component, with each device transfer expressed as an atomic bounded extraction/insertion transaction against the current component identity. On topology split, deterministically partition mixture by physical pipe volume (or another owner-approved rule) and conserve each gas species and thermal energy; on join, merge stores once. Never duplicate contents when component IDs change, chunks reload, or graph rebuilding retries. Requires explicit component lifecycle and stable serialization ownership; this is a recommendation, not a settled storage format.

## Numeric limits and owner decisions before implementation

No numeric caps are currently settled. Owners must record: maximum network nodes and edges per component; maximum pipe capacity per tile/segment; maximum gas amount and temperature bounds; solver/transfer cadence (current candidate atmos cadence: 2 ticks); maximum gas moved per device update; component rebuild work per tick; maximum active scanners, radius in world units, candidates examined and target records per update; packet bytes/rate per observer; scanner update interval and expiry. Scanner radius must be genuinely 3D and bounded, not assumed to be SS14's 4-tile reference default. Decide gas serialization across unload/restart, split allocation policy, explicit finite scrubber waste storage/capacity/full behavior, power meter/service and interval/remainder semantics, and placement eligibility interaction range/permissions. Controlled-body-only placement is fixed. Scanner cable concealment is presentation-only and is not confidentiality.

## Acceptance tests required for later milestones

1. Network graph tests: add/remove edge, branch split and rejoin, repeated rebuild, chunk unload/reload, restart/save-load; each gas species and thermal quantity conserved exactly within declared numeric tolerance, with no clone/loss.
2. Atomic transfer: competing vents/scrubbers and capacity exhaustion never overdraw or double-credit; failed insertion leaves source unchanged; finite scrubber waste fills and has explicit stop/backpressure behavior.
3. Cadence/billing: over equal simulated elapsed time, power billed identically at 20-tick allocation cadence regardless of 2-tick atmosphere calls; partial service and topology changes produce the selected prorated result without duplicate billing or unbounded rounding drift.
4. Controlled-body placement: requests for another body, stale control during transfer, out-of-range target, invalid/occupied target, and unauthorized placement fail; valid placement uses only the settled controlled character.
5. Scanner query: exact spherical inclusion/exclusion in 3D across floor/chunk edges; loaded-only query; cables and pipes independently classified; scan causes no network mutation or chunk load. Candidate and response counts obey owner-approved caps.
6. Two-observer packets: reveal payload goes only to the authorized observer and expires on stop/unwatch/disconnect. Separately assert ordinary cable snapshots still disclose coordinates to an instrumented modified client; this is a documented presentation-only limitation, not a failed confidentiality guarantee. Do not include unauthorized gas-pipe coordinates in scanner packets.
