# M0 host and actor contract audit

**Status: research record only; M0 gate NOT PASSED.** This documents source seams and a proposed fail-closed contract, not owner approval or feature behavior. It does not authorize implementation beyond the separately approved plan's staged scope. Disposal tubes are excluded. No source, code, assets, or media have been copied.

## Scope and reference boundary

The controlling scope is [`../plan.md`](../plan.md): one held gas segment item may install a one-block sealed wall segment; disposal remains a later independent sprint. The broader future proposal at `docs/future-gas-and-disposal-piping-sprint/` describes conceptual constraints but is not platform proof. It specifically leaves host proof, protection integration, persistence recovery, and removal interaction unresolved. Per the approved plan, no numeric bounds, costs, permissions, or owner approvals are inferred here.

The plan identifies local `AtmosphereTopology`, `CableSpoolItem`/`CableStorage`/`CableChunkData`, `ModDataAttachments`, power topology invalidation, and the body/hand authority seams as audit targets. Their existence does not provide a gas-pipe host/segment API. `CableSpoolItem` is cable installation, not a gas-segment precedent. Cable storage/attachments/topology lifecycle can inform questions only after a source-level parity review; they do not establish sparse gas persistence, incarnation semantics, or privacy. In particular, scanner queries must not use mutating `CableStorage.get/has` per the plan.

### Evidence actually established in this audit

- The approved plan states the intended invariants and names local files/classes, but is not itself proof of implementation or an owner-approved contract.
- **Local host/topology evidence (line numbers refer to the inspected files):** `AtmosphereTopology.isPassable(LevelReader, BlockPos)` (21-25) delegates full-block classification to `BlockState.isCollisionShapeFullBlock`; the policy (41-50) treats air as passable, doors/trapdoors/gates by OPEN state, and all other states as sealed only when collision is full. This is a one-cell atmosphere approximation, not a face-specific gas-tightness predicate. `CableStorage.eligible` (102-107) rejects air/barrier and requires a sturdy clicked face plus collision shape equal to `Shapes.block()`; it proves only cable host eligibility, not atmospheric sealing. `CableStorage.loadedChunk` (143-147) asks for FULL status with `create=false`; `get/has` use only existing attachment data (20-40), but prune changed hosts and may mutate stale cable records, so they are not safe precedent for read-only scans. `place` (42-55) creates/writes cable data, marks the chunk unsaved and invalidates cable/power views; it is not transactional gas placement.
- **Host replacement/event limits (current local source):** `StationFloorBlock.onRemove` calls `CableStorage.removeHost` only when `!state.is(newState.getBlock())` (`src/main/java/com/juicyslew/moonstation14/ms14/power/floor/StationFloorBlock.java:27-33`); this is different-block-type cleanup, not same-type replacement/incarnation detection. `CableStorage.hostIdentity` stores only `BuiltInRegistries.BLOCK.getKey(...).toString()` (`.../power/cable/CableStorage.java:139-141`), so same-type replacement has the same identity. Atmosphere placement, break, and neighbor hooks notify topology (`.../atmos/world/AtmosphereEventHooks.java:47-66`), while `PowerGraphService` explicitly cautions block events are hints because direct `setBlock(..., 3)` callers do not all emit them (`.../power/graph/PowerGraphService.java:138-156`). Therefore these hooks and cable behavior do not establish exhaustive same-type host replacement/incarnation proof for pipe installation; direct mutation cannot be assumed to be covered. `PipeChunkData` explicitly says host metadata is only a persistence hint and never establishes current seal or identity (`.../atmos/piping/PipeChunkData.java:132-148`). Its stored host/incarnation strings are not, by themselves, proof that either is checked against live world state or advanced on replacement.
- **Cable persistence/lifecycle precedent, not gas proof:** `CableChunkData` uses a versioned codec and a 4096-record cap (13–38), keys sparse records by local xyz/face/tier and stores a host string (40–55, 154–164); decoding rejects unsupported versions, excess records, and duplicates (123–142). `ModDataAttachments.POWER_CABLE_CHUNK` is serialized only when nonempty and has no `.sync(...)` call (191–196), while `ATMOSPHERE_CHUNK` likewise persists sparse state without sync (184–189). Neither attachment declaration proves crash atomicity or incarnation safety. `CableStorage.hostIdentity` is only the registered block identifier (139–141), so same-block replacement is indistinguishable; replacement cleanup and validation are limited to cable lifecycle paths (90–100, 109–137).
- **Actor and target evidence:** `HandActorAuthority` exists at `src/main/java/com/juicyslew/moonstation14/ms14/hands/HandActorAuthority.java`. `resolve` (42-80) accepts exactly one lifecycle/harness authority and character body, validates the spectator server actor/body, capability and persisted hands, and returns a snapshot; `revalidate` (82-86) re-resolves it. These methods establish body identity, but do not themselves establish an exact held-item token or authorize world placement. The separate `BodyHandRequestService` checks issued-state admission (`src/main/java/com/juicyslew/moonstation14/ms14/hands/network/BodyHandRequestService.java:29-45`), compares the requested expected token against the requested hand's live token (`:130-131`), and revalidates actor/attachment/revision before the hand operation (`:154-173`); `BodyHandStateService` requires an issued query state and builds snapshots from `LIVE_HANDS` (`src/main/java/com/juicyslew/moonstation14/ms14/hands/network/BodyHandStateService.java:36-71`). Thus the established hand guarantee applies through that request/state protocol: exact issued state plus the controlled body's live attachment, revision, and token—not from `HandActorAuthority` alone, nor automatically to a separate placement route. `BodyActionAuthority.resolve/revalidate` (24-65) similarly returns/rechecks a controlled-body snapshot; `eligibleForComplexInteraction` (67-70) is a revalidated status predicate, not placement authority. `ApcBodyTargetProbe.probe` (40-85) provides a bounded, server-body-origin ray hit against already-loaded chunks, but explicitly is a read-only APC sight probe, not interaction/mutation authority; its getter caveat (22-26, 98-126) notes callbacks can independently load chunks. `CableSpoolItem.useOn/allowed` (14-30) checks exact clicked position/face, distance, `mayInteract`, and `mayUseItemAt`, then calls cable placement and consumes an item. Those vanilla checks are concrete cable behavior only; they do not establish the required gas action's approved permissions, controlled-body hand semantics, sneak contract, or protection policy. No reviewed project-owned gas-placement protection API or owner-approved permission identity is established.
- **Pinned upstream evidence:** the checkout was inspected and `git rev-parse HEAD` returned `c9df5ef5d675b0d1d226828bddf6b78c28502d91` as pinned. `Resources/Prototypes/Entities/Structures/Walls/walls.yml` defines `BaseStructureWall` with `Airtight`, inherited by its wall descendants; that is not every block/wall, and other entities explicitly attach the component. `Content.Server/Atmos/Components/AirtightComponent.cs` defines directional airflow-blocking state, while `Content.Server/Atmos/EntitySystems/AtmosphereSystem.Utils.cs` combines Airtight data from anchored entities on a tile. Separately, `Resources/Prototypes/Entities/Structures/Piping/Atmospherics/pipes.yml` defines gas pipe entities with anchored transforms and `NodeContainer`/`PipeNode` nodes; `Content.Server/NodeContainer/Nodes/PipeNode.cs` connects nodes by pipe direction/layer. These are independent co-located entities/nodes, not pipe data stored in a wall; pipes may be built on impassable tiles. Entity UID provides entity identity useful for distinguishing replacement, but does not imply automatic destruction of another co-located pipe on wall removal. This is provenance/context only, not Minecraft API or authorization to port.
- **Local parity distinction:** `AtmosphereTopology` currently defines cell passability using full collision and openable-block rules; it does not expose an SS14-style Airtight component. `SealedWallHostEligibility` is a separate Minecraft-specific opt-in policy, needed only for the requested one-block concealed segment. It must not be described as SS14 parity, nor substituted for true atmosphere blockage. A parity-first design keeps the host admission check separate, preserves the user's unchanged full-collision/no-AIR requirement, and gives pipes independent identity and finite gas. Changing local atmosphere blockage to a component model is an atmosphere-owner migration, not silently done here. Identical block replacement at the same coordinates can leave position-keyed segment state looking valid; SS14 host entity UID helps distinguish replacement of the host entity, but does not solve co-located pipe cleanup or automatically delete the pipe. No identical-block replacement solution is claimed; local same-type replacement/incarnation handling remains unproven.
- Exact NeoForge/Minecraft API source proof for block-state mutation, full collision, atmosphere seal classification, block incarnation, chunk-loaded checks, data attachments persistence, save interruption, packet filtering, interaction face/reach, and rollback was not established in this doc-only audit. No API is claimed to exist or to provide an atomic transaction.

## Proposed contract: one controlled-body, one-host installation

This is the recommended M1 contract, conditional on exact APIs and owner decisions being proven. Until then, reject the action without changing world or inventory state.

1. **Actor/item authority.** Accept only a server-validated action issued by the player controlling an eligible character body, carrying the corresponding gas segment item in that body's exact settled live hand/session. Do not authorize a spectator carrier, free/uncommitted player, stale hand/session, client-supplied actor substitution, or a merely visual held-item claim. `HandActorAuthority.resolve/revalidate` and `BodyActionAuthority.resolve/revalidate` exist as read-only actor snapshots, but neither is itself item-use or world-placement authority; verify exact live-hand/request integration and approval before use. No new or inferred permissions.
2. **Target and intent.** Require sneak-use and server evidence for the exact clicked block position, clicked face, eye-origin hit/reach, and loaded target. Recompute/validate from authoritative server state; do not trust a client position, face, distance, or sneak assertion without the source-defined input contract. Reject occluded/out-of-reach/stale requests. Change at most the clicked host record; never probe/place beyond it or load a neighboring chunk.
3. **Eligible host proof.** Fail closed unless a verified local predicate proves the clicked existing block is full-solid, full-collision, and sealing under the same semantics used by `AtmosphereTopology`, including modded states. Do not assume a special `pipeage` property, infer airtightness solely from collision, or use a permission not found in a reviewed owner-approved API. Snapshot exact original block state and verify it remains unchanged after the action. The pipe action cannot replace the block, set AIR even transiently, alter collision/passability, or change room topology.
4. **Capped until reciprocal verification.** A newly installed segment is incomplete and capped. It cannot transfer gas to room atmosphere. Treat a pass-through as a network edge only after compatible reciprocal ports, both endpoint records, host identities, and loaded status have all been verified. Unknown, unloaded, incompatible, or stale endpoint means capped/disconnected; never force-load or guess a neighbor.
5. **Loaded-only bounded edit.** Read/write only already-loaded target data within owner-approved budgets. Plan must specify the true loaded-only API and bounds. No world scan, far-side placement, or partial write. On any failed validation or failed persistence/commit step, leave host and segment inventory unchanged (or use a reviewed recoverable transaction if ordinary rollback cannot be proven). Do not claim crash atomicity without durable journal/recovery evidence.
6. **Identity and lifecycle.** Store explicit segment type, orientation/ports, unique identity and host incarnation/version, separate from ordinary host block state where possible. A same-type replacement at identical coordinates must advance incarnation or otherwise be distinguishable; it must not inherit a previous segment or edge. On block replacement, invalidate the record/edges before any topology reuse. Chunk unload suspends graph knowledge; reload reconstructs only from durable valid records after current host identity/type checks. Save interruption and failed sync recovery remain unproven and require design/test evidence.
7. **Separate exposed run and removal.** Represent exposed 3D gas runs as their own openly visible segment/port model, not as hidden wall-block data or a 2D wire shortcut; exact shape, attachment, overlap, rendering, and connectivity rules require owners. The wall crossing is a narrow one-host concealed record. Removal interaction/input/tool, access side, cost, and granularity remain open; do not invent a pry/drill tool or let install action remove anything. Thick-wall access remains manual demolition/rebuild farthest-to-nearest, separate from pipe action.

## Targeted acceptance gates (future tests; none run here)

1. **No host mutation:** before/during/after install, assert exact host state, full collision, and `AtmosphereTopology` passability unchanged; instrument every intermediate write to prove zero AIR and zero room gas/topology change, including failed commit.
2. **Actor/hand adversarial cases:** controlled body with matching item/live hand succeeds; spectator carrier, free/uncommitted player, stale/replaced hand/session, wrong item, forged actor, and client-only held claim all fail with no block or inventory mutation.
3. **Target validation:** wrong face/position, eye-hit mismatch, out-of-reach, obstructed, no sneak, stale state, and protected/denied target fail closed. Verify only exact clicked full block can change and establish actual reviewed protection source; do not test a guessed permission.
4. **Host eligibility:** test known airtight full-solid host, non-sealing solid host, partial-collision host, air/fluid, and a modded/unknown state. Only hosts whose exact approved proof succeeds may install; unknown fails closed.
5. **Ports and caps:** isolated segment remains capped; unmatched type/orientation/port, missing reciprocal record, stale endpoint, and unloaded frontier remain disconnected and cause no room-air exchange. Compatible edge forms only after both sides verified loaded.
6. **No loading/remote scope:** place near a chunk boundary with far side unloaded; action never loads it, never installs remotely, and leaves it untouched. Instrument chunk-load requests and target writes.
7. **Incarnation and persistence:** remove/replace host with the same block type at the same position, then different type; old identity never reconnects. Save/restart/unload/reload and injected ordinary failure recover without stale edge, lost/duplicated segment, or host alteration. Crash atomicity is a separate claim requiring recovery evidence.
8. **Removal and geometry gate:** verify install path cannot remove; defer removal assertions until owners select interaction. Exposed 3D runs are tested as separate representation once geometry/overlap rules and rendering owner approve them.
