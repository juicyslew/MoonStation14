## Gas network and room devices

- `Content.Server/NodeContainer/Nodes/PipeNode.cs:107-110` gives each PipeNode a default volume of 200 L. `Content.Server/NodeContainer/NodeGroups/PipeNet.cs:46-47` adds each connected node's volume into the network mixture, so network volume is the sum of its pipe-node volumes. This 200 L is **per node**, not an entire network capacity. Do not mistake a pipe-node capacity for a scrubber rate.
- `Content.Shared/Atmos/Piping/Unary/Components/SharedVentScrubberComponent.cs:12-26` defines the normal selected scrubber gases: carbon dioxide, plasma, tritium, water vapor, ammonia, nitrous oxide, and frezon. The same component's default `VolumeRate` is 200 L/s (`:12-16`); server default transfer rate is bounded by `Atmospherics.MaxTransferRate` (`Content.Server/Atmos/Piping/Unary/Components/GasVentScrubberComponent.cs:35-51`, and `Content.Shared/Atmos/Atmospherics.cs:364-371`). Scrubbing routes selected gas into the outlet pipe; siphon mode transfers all gas instead of filtering (`Content.Server/Atmos/Piping/Unary/EntitySystems/GasVentScrubberSystem.cs:91-128`). This is not deletion: the output is held in the finite pipe mixture.
- The scrubber update requires not welded, powered, enabled, and a valid outlet node (`Content.Server/Atmos/Piping/Unary/EntitySystems/GasVentScrubberSystem.cs:53-72`). Its power check is separate from its `Enabled` state. The vent update likewise checks welded, powered, then enabled and pipe node (`Content.Server/Atmos/Piping/Unary/EntitySystems/GasVentPumpSystem.cs:68-84`). Consequently delivered power gates transfer irrespective of the configured enabled state; enabled/weld are additional operational conditions, not power semantics.
- Do not assign the scrubber's 200 L/s to a room vent. The room-facing pump uses a pressure-change speed: `Content.Server/Atmos/Piping/Unary/Components/GasVentPumpComponent.cs:111-122` says `TargetPressureChange` is in kPa/s and defaults it to `Atmospherics.OneAtmosphere` (101.325 kPa/s). Its normal external bound defaults to one atmosphere in `Content.Shared/Atmos/Piping/Unary/Components/SharedVentPumpComponent.cs:13-26`; the server component also defaults to one atmosphere (`Content.Server/Atmos/Piping/Unary/Components/GasVentPumpComponent.cs:83-104`). Maximum target pressure is 4500 kPa (`Content.Shared/Atmos/Atmospherics.cs:364-371`, used by `Content.Server/Atmos/Piping/Unary/Components/GasVentPumpComponent.cs:107-112`). The separate 200 L/s reference belongs to volume-rate devices such as scrubbers and volume pumps, not this default vent pressure control.

## Power and cadence

- Both devices use a 5 W constant APC receiver: the shared receiver initializes `DesiredPower = 5` in `Content.Server/Power/Components/ApcPowerReceiverComponent.cs:53-58`. Use as first-reference default where meaning maps; it does not establish watt equivalence or justify changing the unrelated local APC battery model.
- Upstream `BatteryRampPegSolver` receives elapsed `frameTime` (`Content.Server/Power/Pow3r/BatteryRampPegSolver.cs:37-44`) and uses it in power/network solving and battery charging/discharging (`:96-135`, `:174-223`, `:266-273`). This is continuous network metering over elapsed time, not prepaid per-gas-step billing or a gas-volume tariff. The planned local adaptation is continuous metering across its 20-tick solve with stale-grant validation; this is a design direction, not implemented live billing.
- Upstream atmosphere config defaults are 15 ticks/second and speedup 8 (`Content.Shared/CCVar/CCVars.Atmos.cs:126-138`). A cell volume is 2500 L (`Content.Shared/Atmos/Atmospherics.cs:64-67`), while grid tile size scales that volume in `Content.Server/Atmos/EntitySystems/AtmosphereSystem.Utils.cs:77-85`. Upstream atmosphere adjacency is 2D cardinal directions (N/E/S/W), not 3D vertical neighbors; see `Content.Server/Atmos/EntitySystems/AtmosphereSystem.LINDA.cs` neighbor traversal (e.g. lines 251-275). These are reference facts, not a direct Minecraft mapping: this project is 3D, with different block-volume and vertical-neighbor questions.
- The current local loop cadences noted in the sprint plan are power every 20 ticks and atmosphere every 2 ticks. They remain local design facts, not values to “correct” from SS14's 15 TPS atmosphere cadence. Likewise, the local 5000 W VentLoad ceiling and arbitrary 500 W test demand are not SS14 device specifications; the first-reference receiver default is 5 W. Local APC storage is 1 MJ (`src/main/java/com/juicyslew/moonstation14/ms14/power/device/PowerDeviceRules.java:7-8`), compared with upstream APC prototype charge of 50,000 (`Resources/Prototypes/Entities/Structures/Power/apc.yml:58-65`); these values alone do not establish equivalent energy semantics. Do not silently rewrite existing local power subsystem values or assert power equivalence.
