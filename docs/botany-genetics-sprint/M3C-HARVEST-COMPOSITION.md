# M3C ChangeHarvest composition (foundation)

The source-ordered 27-entry `random_plant_mutations` table now describes ChangeHarvest as a typed `HARVEST` effect with a `PlantHarvestMutation` payload. `PlantMutationSystem` applies the resolved descriptor to that plant instance's immutable `GeneticValue`; modes advance `NO_REPEAT → REPEAT → SELF_HARVEST` and saturate. The effect body consumes no random values: the existing independent table-entry chance roll remains the sole RNG action for this entry. Chance, flags, persistence and ordering are unchanged.

`SeedProfile.Harvest` and its existing lifecycle codec carry the new value, so normal profile inheritance and serialized instances use the same domain. Replacement retains biology, all lifecycle values/markers, chemicals (including inherent metadata), gas maps, packet/product/visual identity and species. Source parity references are [PARITY.md](PARITY.md) lines 34–70 (ChangeHarvest odds and sequence); the pinned SS14 checkout was not present at the documented `../SS14-dev/space-station-14` path in this worker environment, so this slice did not independently re-verify that pin.

This is genetics mutation foundation, **not complete automatic-harvest mechanics**. Existing live harvest/polling consumers have not yet been updated to interpret `SELF_HARVEST`; the parent must update the evaluator's harvest retention branch so both `REPEAT` and `SELF_HARVEST` retain the source plant. Manual-harvest behavior must not fall through to a `NO_REPEAT` interpretation. No end-to-end automatic output behavior or manual fixture is claimed until the separate live-consumer work proves observable output. Unsupported `ChangeHarvest` diagnosis is removed because this typed domain effect is now applied.
