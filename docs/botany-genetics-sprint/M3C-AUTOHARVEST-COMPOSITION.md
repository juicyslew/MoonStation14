# M3C automatic harvest lifecycle

The trusted Minecraft botany fixture initializes its authored finite chamber through `AtmosphereService.initializeEnclosedFiniteMixtureForTrustedSetup`. The supplied-cell and candidate-storage caps remain 1024. Total synchronous search step calls have a separate bound of eight per supplied cell (one seed call, six directional inspections per cell, and a possible completion call); therefore the maximum accepted input entails at most 8192 calls. The method still proves the exact connected, fully enclosed room and validates all targets before writes. This trusted-setup bound does not change runtime discovery/search budgets, exterior policy, or failure/mutation-free proof guards. Authored chamber cells use the Minecraft adaptation's Y+1 feet plane; this is not a claim of SS14 map-composition parity.

The pinned SS14 checkout (`c9df5ef5d675b0d1d226828bddf6b78c28502d91`) runs `PlantHolderSystem.cs:652-653` automatic harvest after `CheckHealth`, and before new readiness calculation at `:655-665`. `AutoHarvest` calls `BotanySystem.Seed.cs:119-131`; `PlantHolderSystem.cs:756-783` invokes `AfterHarvest`, which resets readiness and `LastProduce` to current age and removes only `NoRepeat`. Product generation clamps nonnegative yield to at least one (`BotanySystem.Seed.cs:150-168`); the manual entry point rejects yield <= 0 (`:133-139`).

The local `PlantMetabolismEvaluator` exposes a narrow optional output callback, preserving existing callers. On an actual due cycle, after health/death work and before readiness calculation, it publishes only a plant that was already ready at cycle entry and still lives with `SELF_HARVEST`. The post-growth age/health are stored before callback admission. A successful publication calls the shared `afterHarvest` transition; a failed publication leaves the source ready and retains its prior production timestamp for retry on the next actual cycle. Newly-ready plants wait until the following cycle. Both repeat modes retain the plant; only `NO_REPEAT` clears it. Manual zero-yield behavior remains unchanged; automatic output count is at least one.

The tray consumer uses the same current effective `GeneticValue` and `ProduceFactory.createHarvest` as manual harvest, then `FreshWorldOutputBatch.publishSystemHarvest` at holder coordinates. The existing batch stages collision-checked loose world entities, revalidates the tray/plant/revision/species/genetics/readiness/mode, and commits source state only after output publication. Failure is exposed via the tray's read-only last automatic harvest outcome. This remains a Minecraft world-output adaptation; it does not implement SS14 scream effects. The baseline supported produce catalog is still five products. Native registered-world proof and owner acceptance remain pending.
