# M3B live gas exchange composition

The upstream checkout was verified at `C:/Users/William/Documents/SS14-dev/space-station-14`, revision `c9df5ef5d675b0d1d226828bddf6b78c28502d91`. `PlantHolderSystem.cs` performs exchange on the ordinary 15-second plant cycle, after soil metabolism/mutation and living/dead checks. It consumes each required named gas only when the complete configured amount is present; an insufficient entry is not partially consumed and damages health once per missing species. Pressure uses the actual mixture after consumption. Exudation follows pressure/temperature evaluation; source arithmetic is `max(1, Round(amount * Round(potency) / entryCount))`, using midpoint-to-even rounding.

Local live behavior extends `PlantMetabolismEvaluator` with a narrow `GasExchange` boundary and binds it in `HydroponicsTrayBlockEntity` to the exposed cell above the tray. The effective profile is freshly resolved after the soil/mutation callback and its maps drive that cycle. Consumption and injection delegate to existing strict `AtmosphereService.tryConsumeGas` and `addGas`; pressure/temperature are sampled again after consumption. This deliberately respects finite owned-cell write policy: exterior ambient and unavailable/unknown ownership do not count as successful writes. Empty maps preserve existing evaluator callers; non-empty consume maps without an adapter fail closed. Dead/empty holders do not exchange gas. Gas mutations remain genetic profile changes and are not rolled back or made atomic with world writes.

Zero-amount boundary: upstream checks `available < configured` before adjusting moles, so a configured consumption amount of zero is satisfied even in a zero-mole SpaceGas mixture; it does not call an adjustment and therefore must not require a writable cell or cause missing-gas damage. The evaluator treats that requirement as no world write, without weakening `AtmosphereService` ownership rules for positive consumption. Exudation differs: its source `max(1, Round(...))` minimum means a zero configured exude amount still requests a one-mole injection and can fail the finite-cell write policy.

The evaluator returns the cycle outcome in `Result.gasExchange()` (`attempted`, `missingGasCount`, `unmetRequiredGases`, and `failedExudationGases`). A failed `addGas` is reported by its gas type; it does not apply extra plant damage or roll back genetics. Existing four-argument `Result` construction remains source-compatible with a no-attempt report. The tray exposes `gasExchangeReport()` as the last actual living-cycle report and does not replace it with skipped/no-cycle/dead-holder outcomes. This is an operator/fixture status projection, not a gameplay analyzer.

Adaptation boundary: Minecraft tray exposure is mapped to `pos.above()`, rather than SS14's atmosphere entity/container. Exudation uses the current sampled mixture temperature to preserve mixture temperature through `addGas`. Existing named gas identity and strict write contracts are reused; no second solver, registry, analyzer UI, transaction, or per-tick exchange is introduced.

Focused gas lifecycle tests and native fixture validation remain to be supplied/run by the parent integration pass; this document and implementation are not evidence of a native registered-world fixture or readiness/full-suite pass.
