# Seed restoration feedback

Sedin's upstream `PlantRestoreSeedsEntityEffectSystem` (`c9df5ef5d675b0d1d226828bddf6b78c28502d91`, lines 9–23) applies ordered effects (health -2, restore seeds, potency -3); `Sedin` in `Resources/Prototypes/Reagents/Chemistry/Botany.yml` lines 159–173 defines that sequence. Successful restoration uses `botany-plant-seedsrestored` from `Resources/Locale/en-US/botany/seeds.ftl` line 1. Local feedback intentionally follows committed tray metabolism: it is queued only when a living seedless plant actually transitions and sent after the poll's publish. Already-seeded, dead, absent, failed-chance, invalid-poll cases produce no notice. This does not alter reagent ordering or probabilities.

The upstream immutable property belongs to `SeedData` instances (default false), not a biological trait. Upstream clone behavior asserts non-immutable input and creates a mutable clone while retaining uniqueness; normal reagent updates ensure uniqueness before effects. Locally, immutable genetic profiles are value data and `ensureUniqueSeed` provides the mutable plant-instance boundary. No new prototype field is needed; the notice requires a living current seedless plant, preserving copy-on-write reference behavior.

Presentation reuses `PopupMessageEffect`'s existing `Small` gray translation/style and actionbar delivery owner. The coordinate entry targets only players tracking the tray's chunk; there is no global or proximity fallback. Minecraft actionbar and chunk-tracking visibility are deliberate adapters for upstream entity PVS small-popup delivery, not world-anchored text or visual parity. Delivery is best effort after authoritative state commit and cannot roll back gameplay.

The successful normal Sedin outcome remains chance-based; no outcome or timing is promised. Extracting fresh harvest remains stronger proof than an old failed produce reference, which is not rewritten by copy-on-write. This notice is not an analyzer, numeric HUD, or hidden-roll disclosure.
