## Seed records are not entity prototypes

`Resources/Prototypes/Hydroponics/seeds.yml` entries are `seed` prototypes, deserialized as `SeedPrototype : SeedData` in `Content.Server/Botany/SeedPrototype.cs`; they do **not** inherit the entity prototype `SeedBase`. `SeedData`'s omitted values are effective defaults: growth stages 6; growth rate/consumption and tolerances as encoded by the source schema; and its initialized genetic maps/lists. `SeedPrototype` adds prototype identity and is the shared immutable source. `PlantHolderSystem`/`BotanySystem` clone mutable seed data for a holder when copy-on-write is needed; holder age, health, weeds, resources, readiness and mutation counters are holder state, not seed genetics. Source: `Content.Server/Botany/SeedPrototype.cs`, `Content.Server/Botany/Systems/PlantHolderSystem.cs`, `Content.Server/Botany/Systems/BotanySystem.Seed.cs`.

## Deliberate boundaries and evidence

- The carried value is an immutable **snapshot** for the foundation's repeated-harvest/multi-yield packet/product transmission. Upstream defaults `Unique=false`; repeated/multi-yield generation explicitly marks shared seed state, after which a later mutation clones before changing it. Do not generalize snapshot semantics to every transfer: pollen captured from an upstream `Unique=true` seed can observe later in-place changes. A live pollen alias/reference owner is future work and is not implemented.
- This profile carries only fields the local runtime supports. Common physical components map to supported `LooseItemEntity`/registered item-prototype behavior, not exact SS14 physics. Labels, clothing, destruction, machine/crafting, food effects, paper-label interactions, powerslots and produce actions are unsupported; all generated food chemistry wipes initial contents. No parity is claimed for omitted systems.
- Local genetics initialization uses the resolved typed profile including inheritance/defaults; packet icons are reused Minecraft presentation, not full SS14 seed-data/component rendering. Local default representation and lifecycle validation are adaptations, not byte-for-byte `SeedData` equivalence.
- Prototype/inheritance checks: `SeedProfileTest`; tray/profile checks `HydroponicsTrayLifecycleTest.resolvedNormalAndEmptyProfileValuesAreTheInitializationInputs`, `TrayRulesTest.geneticsPersistAsIndependentInstanceSnapshots`, `TrayRulesTest.resolvedTrayInheritanceHasNormalAndEmptyDefaults`, `ProduceProfileTest.resolvedProduceAndIngestionSourcesAreUniqueAndComplete`, and `BotanyMachineProfileTest.resolvedMachineInheritancePreservesExtractorAndGrinderDefaults`.
