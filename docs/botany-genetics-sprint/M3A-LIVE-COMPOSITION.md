# M3A live mutation cycle

Reference composition verified against SS14 `c9df5ef5d675b0d1d226828bddf6b78c28502d91`, `Content.Server/Botany/PlantHolderSystem.cs` (mutation cycle), `PlantHolderComponent.cs` (level/modifier), and `Resources/Prototypes/Hydroponics/randomMutations.yml`. The resolved local `PlantInstance` owns holder mutation level (default 0, clamped 0..100), modifier (default 1, clamped 0..3), and immutable effective `GeneticValue`; mutation data is not put in the seed profile.

`HydroponicsTrayBlockEntity.tick` runs the existing reagent metabolism poll before a due cycle. At a due cycle, `PlantMutationSystem` caps positive level to 25, preflights all applicable chemical-table references before changes, then independently rolls each table entry in source order using strict `<` and one `nextDouble` per entry (including zero/one odds). Supported stat effects extend `PlantStatMutation`; chemical effects extend `PlantChemicalMutation`. Successful profile changes replace the plant's immutable genetics/revision, protecting previously emitted products. Growth resolves the effective profile only after the mutation callback, avoiding stale-profile growth.

Supported scope is the stat and chemistry effect classes currently consumed by local domains, including biology/lifecycle inputs used by growth and future harvesting. Capability entries still roll in position but are returned in `PlantMutationSystem.Result.unsupported` as explicit name/kind diagnostics. This is not full 27-entry gameplay parity. Species, gases, harvest mode, sentience, slippery contact, ligneous tool semantics, kudzu coexistence, scream, and live pest state consumers remain unsupported. Source RNG consumption can consequently diverge where an unsupported effect's body would itself consume RNG; later capability units must preserve that ordering. No extra predicted-probability draw is made because all current source entries use default probability 1.

Upstream `PlantHolderSystem.cs:493-498` applies nonviability as `AffectGrowth(-1)` plus `6 * healthMod` damage every living cycle; existing starvation aging logic is retained. `:456-461,608-618` adds .5 pest level with 1% chance per living cycle and damages one health when pest level is positive and strictly exceeds seed pest tolerance. The persisted tray pest level is holder state, clamped 0..10, and inherits resolved pest tolerance default 5 (`SeedPrototype.cs` / `SeedData`); death clears pest level as upstream `:796-812` does. This maps actual tolerated pest damage, not the separately unimplemented pest-reduction/weed species behavior.

Upstream harvest `BotanySystem.Seed.cs:133-148` explicitly denies manual harvest when base yield is <=0 (no output), but `PlantHolderSystem.cs:730-731` still runs `AfterHarvest`; the lower-level product loop also guards zero yield to at least one only for yield >=0 (`:150-168`), while `AutoHarvest` directly calls it. Local exact preview/commit reports count zero for zero effective yield and does not fabricate one. The separate authenticated use/publication consumer must resolve whether its zero-output path commits the corresponding source harvest (manual denial versus auto-harvest) before ownership changes; this evaluator does not commit outputs.

Local composition intentionally adds no invented care requirements. Seedless extractor denial remains assigned to its separate consumer owner. No water/nutrient requirement, light, or radiation rules are introduced. Dedicated JVM coverage exercises due-cycle ordering, all-entry RNG draw count, severity/reset, immutable instance isolation, preflight failure, viability/pest damage and zero yield; this is focused evidence, not connected-runtime/native validation.
