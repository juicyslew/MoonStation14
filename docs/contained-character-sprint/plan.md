# Generic contained-body foundation (work unit A; work unit B in progress)

The authoritative level-scoped index and body lifecycle are `ms14.containment.BodyContainmentService`; owners implement `ContainedBodyOwner`, whose `view()` returns immutable `ContainedBodyView(ownerIdentity, worldTarget, cameraCollision)`. Membership remains keyed by the body's UUID and ownership transfer does not restore flags. Original state is `BodyContainmentService.ContainedBodyFlags`.

`ContainedBodyOwner.Stage.STATIONARY` is the generic stationary stage; disposal-unit owners retain `UNIT` for current movement semantics and the snapshot adapter maps either stage to existing movement mode `UNIT`. `TRANSIT` remains transit. Owners can publish no world target while in transit. Unit views publish their immutable block position; transit views publish no target. Generic fixture owners get the default empty-target/camera-collision view. No camera, hands action, or drop/throw behavior is implemented here.

`DisposalEntityData.ContainedViewData` is a supported local composition field, not an upstream YAML/component claim. `disposal_unit_base.json` declares camera collision true and `disposal_holder.json` overrides it false; resolved owners reread catalog data for each view. Presence of a contained-body snapshot is the future client's third-person signal; do not add a redundant force-third-person field.

Parity audit (upstream checkout verified by expert at pinned SS14 revision `c9df5ef5d675b0d1d226828bddf6b78c28502d91`): `DisposalUnit -> DisposalUnitBase -> BaseMachinePowered -> BaseMachine -> BaseStructure`; inherited defaults include 1000W and the machine/structure composition. Holder has no prototype parent; its `ContainerContainer` / `disposalHolder` defaults (`ShowContents=false`, `OccludesLight=true`) come from Robust container defaults. Relevant native code is `Content.Server/Containers/Systems/ContainerSystem.cs`, `Content.Shared/Transform/Systems/SharedTransformSystem.cs` (`DropNextTo`), and `Content.Shared/Hands/EntitySystems/SharedHandsSystem.cs` (`ThrowHeldItem`): drop attempts same-container insertion then falls back to owner world position if rejected; throw denies before hand removal/cooldown splitting. These actions are not implemented here. Third-person camera/collision configuration is an explicit Minecraft adaptation, not an unsupported SS14 YAML component. `ShowContents` eye behavior is not claimed as Minecraft camera parity.

Sprint order: A generic owner/view and lifecycle contract (complete); B snapshot/client camera interpretation; C server hands/drop/throw interactions. Keep their ownership boundaries separate. No new container types or entity-target UI protocol are included in A.

Work unit B camera implementation note: character snapshots carry the optional authoritative `ContainedBodyView`; the client perspective lease is keyed by exact body UUID and committed epoch (owner identity may change during transfer). A contained view forces rear third-person and restores the captured perspective when the lease ends. The `cameraCollision=false` view bypasses only vanilla detached-camera zoom clipping for the exact currently owned body. These are Minecraft client adaptations; entity physics and ordinary world rendering remain unchanged. Minecraft 1.21.1 `Camera` signatures verified from mappings.dev / NeoForge Javadocs: `setup(BlockGetter, Entity, boolean, boolean, float)` and private `getMaxZoom(float): float`.
