# Power sprint — current owner handoff

## M10 cable visual regression status

The reported floor-cable reveal, initial wall-cable snapshot, APC/LV tint, and ordinary wall-occlusion fixes are documented in the [M10 visual regression audit](audits/m10-cable-visual-regressions.md). Floor tile placement/prying notifies the visual hook only after a successful state change; cable records and graph membership are untouched. Client snapshot recovery is bounded to loaded chunks, prioritizes loaded chunk-watch candidates with nearby 3x3-window fallback, and sends at most two requests per client tick. An unanswered first request is retried after 30 ticks, then after 60, 120, and at most 200 ticks. The server validates watcher/FULL-chunk status and enforces bounded queue, packet, byte, and record budgets; responses go only to the requesting client. APC/LV uses normalized SS14/Robust green `(0,128,0)/255`. Cable rendering sets LEQUAL depth testing, disables depth writes while drawing, restores render state, and skips empty geometry. This describes implementation paths, **not manual visual acceptance**: graphical world behavior remains NOT MANUALLY VERIFIED. SS14 sprites have not been copied, so final SS14-textured fidelity remains deferred. M10 ordinary occlusion is not the future T-ray scanner; [that document](future-t-ray-scanner.md) is a planned future milestone only, and gas-pipe ownership is not yet established. Owner validation remains outstanding for both tile finishes, initially loaded wall cable, fancy/fabulous occlusion, chunk unload/reconnect with two clients, and integrated singleplayer; see the linked audit checklist.

## M8 debug starter station (2026-09-27)

### M9 starter-station power integration (2026-09-28)

The new-world-only placement worker now applies the immutable `StarterStationPowerPlan` after all footprint/circuit chunks, support, structure, overlays, entities, and cable-face conflicts pass read-only preflight. It writes floors/walls/air before the planned steel cable hosts, typed devices, and cable records; exact device kind/facing is idempotent regardless of lamp `LIT`, and already-present cable tiers are retained. SavedData reaches COMPLETED only after device/host/cable verification. APC block entities are not rewritten on a matching retry, preserving battery/breaker state. Power devices are generated independently of the simulation toggle. The marker-backed lifecycle GameTest passed in an isolated fresh-world run: it checked completion, 400 tiled floors, seven device kinds/facings, every planned cable record, room/entrance, and all four lamps lit with emission 14 under the enabled simulation gate within 120 ticks. Disabled-mode darkness and actual stop/restart remain unobserved.

The new-world-only Overworld starter-station path is implemented in `ms14/station/debug`: vanilla's new-level spawn-initialization event records a pending SavedData marker, while a post-server-tick worker retries bounded loaded-only footprints, persists the chosen origin, and records completion. The ordinary cancellable event listener filters by server-level Overworld dimension key (not an early `server.overworld()` pointer comparison) and does not cancel or change vanilla spawn initialization; it also does not use the power simulation enable switch. The placement plan reuses `StarterStationLayout`; all layout floors become tiled station-floor blocks, and structure placement waits for full preflight. Preflight has an O(1) pure coordinate-to-material lookup, freezes and reuses a terrain-based support plan (up to three support blocks of terrain variation), rejects fluid at all non-exact-intended planned write positions, and runs no more often than every 40 server ticks.

`LevelEvent.CreateSpawnPosition` uses the normal bus listener; “observer” means that the handler does not cancel this ordinary cancellable event, not an event priority. Only this new-level event creates the marker; old worlds without marker data are not initialized by the retry worker. A fresh isolated server-world GameTest run now verifies the fresh-world lifecycle and station placement (details in the [M8 audit](audits/m8-debug-station-placement.md)); existing-world non-generation is not end-to-end tested. Crash recovery and restart behavior remain unverified. If no safe loaded site exists, state remains pending rather than forcing chunks or overwriting non-replaceable terrain or fluids. Support planning reads terrain beneath the selected floor instead of trusting a heightmap that may include partial station writes, allowing exact intended supports/structure to be resumed while rejecting other obstructions.

**Status: implementation is present through M16, but the sprint is not accepted.** This is an evidence/status handoff, not a declaration that owner acceptance gates have passed. The coordinator-verified compile/unit-test command and isolated server-world GameTest run passed; the latter completed all 159 required tests. Client/two-client/restart behavior, manual appearance and first-spawn timing, existing-world non-generation end-to-end behavior, and 20-player station behavior have not been verified. ## What is implemented (code presence and existing audit evidence)

- **Floor substrate and finishes:** a registered station-floor substrate with `none`, `steel`, and `white` finish variants; separate steel/white tile items and a separate registered floor-tile pry tool operate on the same floor block. The registered crowbar remains a wall/girder tool only. Floor/tile interaction GameTests use the separate pry tool and are present for server-world execution. Tile state is ordinary BlockState; cable storage remains separate, and removing a finish does not replace the floor host or touch its cable records.
- **Face cable storage and tools:** sparse, versioned chunk-owned cable records for all six host faces and HV/MV/APC tiers, with schema v2 permitting all three tiers independently on one host face. Schema v1 is read/migrated to v2; storage remains loaded-chunk-only with persistence/dirty marking and host-identity validation. Cable spool items place on the clicked face. The cutter uses the mainhand tool and, where the face is ambiguous, a matching offhand coil selects the tier; a lone tier still works without the selector. There is no ticking block entity per cable.
- **Visual sync and placeholder:** bounded chunk-watch snapshots synchronize cable face-tier records to clients, with revisions, queue/retention/frame limits, and client-side procedural tier-colored strips. No SS14 cable sprites or other SS14 images were imported. Tier-colored offset lanes preserve same-face and coplanar quads in positive/negative directions and project consistently around perpendicular corners. With a top tile, all three cable tiers are hidden at that host face; a visible neighboring cable still has a stub aimed at the covered tile boundary, with no cable drawn under the cover. This is procedural corner projection, not finished authored/mitered art, and has no client visual acceptance.
- **Topology and unknowns:** deterministic face adjacency supports coplanar continuations, genuine perpendicular shared-edge contacts, typed device ports, and explicit cable segments for risers. Loaded-world graph discovery uses already-loaded chunks only and keeps queries `UNKNOWN` while refresh/traversal is pending or a possible frontier leads into an unloaded chunk. It does not force-load chunks. Topology and face adjacency have focused pure tests; the current automated server run also passed the cable and graph GameTests. Electrical graph behavior is unchanged by the presentation-only neighbor lookup.
- **Typed power loop/devices:** registered HV fixed source, HV→MV substation, battery-backed MV→APC device, and APC-tier lamp use typed ports. The server-side live loop solves known components on a 20-tick cadence, with bounded source/bridge/load/storage rates; unknown ports fail closed. APC battery state persists in its block entity. Lamps use a nearest known APC/LV internal-tier provider within three 3D blocks measured between block centers; no facing requirement applies. Wrong-tier, out-of-range, and unknown/unloaded graph candidates fail closed, leaving the lamp dark. Lamp `LIT` state is synchronized and maps to actual block light emission (0 off, 14 on). The latest automated run passed all 159 required GameTests; this does not verify manual client behavior, sprites/appearance, or multiplayer behavior.
- **Creative access:** floor, tiles/tools, cable spools/cutter, source, substation, APC, and lamp are listed in the existing MoonStation creative tabs. **Survival recipes are not implemented.** There is **no APC UI**; breaker interaction is a bounded server-side interaction, not a screen/menu.
- **Scale probe:** the standalone `LoadedPowerGraph` benchmark measured the synthetic 20,000-node line at **157 convergence ticks** with a 256-node/tick graph work cap and queue high-water 1 in that workload. This is one local JUnit probe, not a Minecraft station or player-count test. Its rough memory number is an estimate, not measured heap/RSS.
- **Power simulation toggle (M6):** common `enablePowerSimulation` defaults true and is sampled at server-about-to-start. When false, graph/runtime work and runtime device indexing are gated off; cable records, APC energy, registrations, placement/tools, visuals, and creative visibility are retained. Existing lit lamps are darkened when their chunks load, without a recurring world scan. See [M6 audit](audits/m6-power-toggle.md). The disabled-mode chunk lifecycle and true-after-false restart have not been observed in a running server.
- **Graph invalidation and validation:** `PowerGraphService.noteChanged` queues affected work as pending without immediately calling global `graph.invalidate`. Actual cable-node changes and chunk load/unload still trigger a global graph rebuild. Bounded periodic validation can detect host changes that were not observed through normal change notifications, but detection may be delayed until a later validation pass.
- **Chunk return resync:** client unload handling is dimension-aware and only clears that chunk's retry cooldown; it does not reset global retry timing or cursor progress. Chunk loads enter a bounded priority queue ahead of periodic nearby-window repair. Each tick inspects a bounded number of entries and sends at most two snapshot requests, only for client-loaded chunks; no chunks are forced. See [M13](audits/m13-cable-chunk-return.md).
- **First-spawn visuals (M16):** bounded pre-world staging keeps newest snapshots for up to 16 chunks/65,536 records. Missing snapshots are retried after 30 ticks, then 60, 120, and at most 200 ticks. Arrival remains asynchronous and can briefly lag under heavy load. A delayed same-dimension packet in the logout/login gap cannot be identified as stale because the protocol has no session ID; see [M16](audits/m16-first-spawn-wire-visuals.md).

## M0–M5 evidence and remaining uncertainty

The detailed milestone records are [M0](audits/m0-platform-contract.md), [M1](audits/m1-floor.md), [M2a storage](audits/m2a-cable-storage.md), [M2b visual sync](audits/m2b-visual-sync.md), [M3a adjacency](audits/m3a-face-adjacency.md), [M3b loaded graph](audits/m3b-loaded-graph.md), [M4a allocation](audits/m4a-allocation-design.md), [M4b devices](audits/m4b-devices.md), [M4c live loop](audits/m4c-live-loop.md), [M4d integration tests](audits/m4d-integration-tests.md), and [M5 station-scale probe](audits/m5-station-scale.md). The [architecture notes](architecture.md) define intended behavior; the [asset ledger](assets-and-attribution.md) distinguishes reviewed references from imported assets. Read implementation as present where described, not as accepted runtime behavior.

Known limits and open gates:

- `PowerGraphService.noteChanged` queues pending work and does not immediately invalidate the whole cached graph. Actual cable-node changes and chunk load/unload still cause a global rebuild; at the measured work cap, the synthetic 20k line needs 157 ticks to converge. Bounded periodic validation may detect unobserved host changes later rather than immediately. Actual attachment validation/chunk overhead and production dense/burst workloads are not included.
- Stored host registry identity detects replacement with a different block type, but **same-type host replacement/re-place is not distinguished**. Arbitrary mutation paths also do not have a universal interception guarantee; do not claim all stale-record lifecycle cases are resolved.
- Client payload/render behavior has not been observed in a running client or two-client session. Restart/save-reload outcomes, snapshot races in practice, chunk-seam behavior in-world, and client-facing light/render appearance remain unobserved.
- Client pixels/depth and final geometry are not verified in-game. Hidden-neighbor packet privacy and client performance remain open; the rendering rule that suppresses hidden neighbor geometry does not establish payload privacy. The T-ray scanner remains a future milestone only.
- The riser and edge-turn topology rules have pure coverage; tier-offset edge-turn spokes project matching lanes around their shared cube edge. This is procedural geometry, not finished authored/mitered corner art and not an SS14 visual match. No manual client observation of appearance or first-spawn timing has been performed.
- The 20k result is a synthetic graph benchmark, not validation of a 20-player station, full device-solve cost, or actual memory use. There is no APC UI and no survival acquisition path.
- The assets ledger records reviewed SS14 LV/MV/HV sources but **no SS14 sprites have been imported**. Any future image import still needs the exact per-file provenance, attribution, license, modification, and notice ledger.
