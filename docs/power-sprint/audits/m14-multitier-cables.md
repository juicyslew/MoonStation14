# M14 multi-tier cables on a shared host face

Cable chunk attachment schema v2 keys each record by local host position, face, and tier. This allows HV, MV, and APC (LV) records to coexist on one face while retaining a host block identity independently for each tier. Snapshots are ordered by local x/z/y, face, then tier; the attachment remains bounded at 4096 records per chunk.

Schema v1 is accepted as one record per host face and migrated on read to the v2 in-memory representation; subsequent saves encode v2. Duplicate v1 host faces are rejected; v2 rejects duplicate complete host-face-tier keys while accepting distinct tiers on one face. Thus HV, MV, and APC may all independently coexist on the same host face. Face-only lookup/removal returns no result when ambiguous. New exact-tier storage APIs support spool/cutter and graph validation. The cutter uses the mainhand tool and, when multiple tiers make the target ambiguous, requires a matching coil in the offhand to select the tier; a single tier remains removable without that selector.

Graph and renderer architecture are unchanged. Cable visual snapshots validate uniqueness by the complete host-position/face/tier node and continue to cap each packet at 4096 records; the tier remains encoded on the wire. Server bandwidth estimation counts eight bytes per record (x, y, z, face, and tier) plus a conservative packet header, matching the record encoding for aggregate tick-budget fanout. Graph host-change detection probes the fixed six-face by three-tier key space, so an ambiguous face cannot hide a cable host.

Starter-station preflight, installation, verification, and GameTest assertions use exact planned tiers. Additional tiers on a planned face do not block installation, while stale records carrying a mismatched host-block identity are pruned by the storage validation path before the exact-tier check. Core station layout and `PowerTopology` are unchanged, and power connectivity remains tier-separated.
