# M8 — new-world debug starter-station placement

## Intended lifecycle

`LevelEvent.CreateSpawnPosition` is an ordinary cancellable event, registered with the normal `bus.addListener` API. “Observer” describes behavior: the handler never cancels or changes the event. It accepts only a `ServerLevel` whose dimension key is `Level.OVERWORLD`, without comparing it to `server.overworld()` (which may not yet be registered at this event time), and marks the new level pending; vanilla spawn initialization and final spawn selection remain deferred to vanilla. This event is the only path that creates the marker. The post-tick path uses the non-creating `DimensionDataStorage#get(Factory, String)` API, so older worlds with no marker do not get one on load. Pending/selected/completed state and selected origin are stored in Overworld SavedData. `StarterStationLifecycleGameTests` now observes the actual overworld SavedData lifecycle and world blocks: a missing marker is explicitly logged as a skipped legacy-world test, while a present marker must complete within 300 ticks and then pass placement assertions. It never force-loads chunks or mutates runtime placement state.

## Placement safety and limits

Retries examine at most eight deterministic footprints near the vanilla shared spawn on a 40-tick interval and do not force chunks. Every intersecting chunk must already be FULL before any height/block read. The chosen origin is stored before placement; completed data never repeats. The bounded preflight requires dry replaceable floor/headroom or the exact intended placed state, sturdy dry terrain beneath every floor cell, no living entities in the volume, and at most three support blocks between terrain and selected floor Y. Every planned write position (floor, structure/clearance, and uninstalled support) rejects nonempty fluid unless it is already exactly the intended state; this prevents water, lava, and waterlogged replaceable blocks from being cleared or replaced. Each column's terrain probe checks only the three possible support positions and one ground cell (at most four levels); if no dry sturdy ground is found within that range, the candidate fails closed. It builds one immutable support plan from terrain below the selected floor before any writes, recognizes exact already-installed steel supports, and reuses that frozen plan for the whole placement pass; heightmaps are not sampled again during writes. O(1) direct layout classification avoids scanning/allocating from the million-plus-cell write plan for every inspected block. The retry preflight requires the exact STEEL/WHITE floor finish, so a manually changed installed finish is not treated as station-owned state. Writes are derived from `StarterStationLayout`: every floor maps to the station-floor block with STEEL or WHITE finish; wall and roof cells map to steel wall; interior clearance maps to air. Retries accept already-written exact intended structure states, so an interrupted placement can continue at its persisted origin, while foreign non-replaceable blocks stop placement. The lifecycle GameTest checks all footprint floor finish states, four room interiors, and the two-block open west entrance against actual world blockstates after SavedData reaches COMPLETED.

The support check accepts bounded terrain variation of up to three support blocks per footprint column; no terrain leveling or excavation is attempted. A pending marker remains pending when no safe loaded site is available. This avoids destructive fallback placement but means an unloaded or obstructed spawn neighborhood can defer the station indefinitely. The fresh isolated run at `build/power-fresh-spawn-proof-2` produced `world/data/moonstation14_debug_starter_station.dat`, emitted no skipped-station warning, and completed `StarterStationLifecycleGameTests` assertions for marker completion, all 400 floor tiles, four room interiors, and the west entrance. This is automated new-world server-world evidence, not owner visual/manual acceptance. The existing-world non-generation behavior (that old worlds without a marker remain uninitialized) is still not end-to-end tested. Existing GameTest worlds with no marker produce an explicit logged SKIPPED outcome and do not assert successful new-world placement.

## Validation

Focused tests cover new-world state eligibility, persistence round trips, terminal completion, fluid-aware write-target policy (including water/lava/waterlogged-replaceable cases), direct layout lookup against every planned cell plus block-role mapping, and deterministic support-plan resumption after partial writes. The automated GameTest waits at most 300 ticks for a present marker to complete, then verifies selected origin, all 400 floor finish states, four actual room interiors, and the open west entrance. The isolated fresh-world run was ` .\gradlew.bat runGameTestServer -Pms14GameTestDir=build/power-fresh-spawn-proof-2 --no-daemon`; its log completed 154 tests with six required atmospherics failures and no power or station-test failures. The fresh world produced the station SavedData marker and had no skipped-station warning. This automated result does not replace owner visual/manual acceptance. Focused source gates: ` .\gradlew.bat compileGameTestJava` and ` .\gradlew.bat test --tests '*StarterStation*' --no-daemon`; `git diff --check` was also run for the documentation changes.
