# M4c live power loop audit

## Delivered

`PowerRuntime` indexes power device block entities from chunk-load and block place/remove lifecycle events. It caps an index at 512 entries per dimension, removes stale/unloaded positions, does not enumerate the world or request chunks, and only runs an allocation every 20 server ticks. Cable connectivity is resolved exclusively through `PowerGraphService`/`LoadedPowerGraph` port-node component states. Unknown graph state fails closed. Device ports retain their defined tier and direction: HV source → HV side of substation → MV side/APC input → APC output → APC-tier lamp.

Block lifecycle handling distinguishes block identity changes from blockstate-only updates: placing/replacing a device indexes it, removing/replacing it removes it, and same-block `LIT` changes do neither. A same-block `FACING` change invalidates that chunk's graph topology without re-indexing the device. The pinned Minecraft 1.21.1 mapped `Block` callback implementation was checked locally: `onPlace` is a no-op in the base class, while base `onRemove` removes a block entity only when the new state is not the old block; calling `super.onRemove` for a same-block state transition therefore preserves the device entity. Repeated steady-state lamp projections do not churn the device index or graph cache.

`PowerLiveLoop` performs component-wide accounting with `PowerAllocation`: all known HV sources offer into a single allocation for each HV component's substations, then each substation performs one explicit HV→MV transfer capped at 8 kW and 90% efficiency. The MV component aggregates all substation transfer offers before allocating to APC input (2 kW per APC). Each APC-tier component aggregates APC grid offers, eligible batteries, and all component lamps into one solve. Source output is capped at 10 kW, APC output at 2 kW, lamps request 100 W, and APC storage uses the existing 1 MJ capacity plus 1 kW charge/discharge rates. Unknown ports are excluded rather than treated as connected. The APC breaker gates that APC's output and battery participation; closed breakers charge from available grid surplus, and open breakers neither charge nor discharge. Every APC energy value is projected once from the aggregate result per solve. Every lamp receives one final lit-state projection per solve, independent of the number of APCs sharing its component. Lamp `lit` state is server blockstate-synchronized; APC energy remains in the block entity's existing NBT. Generation is not persisted or accumulated while disconnected.

## Limits / follow-up

This is a bounded live slice, not station-scale acceptance or a globally optimized multi-tier flow solver. Independent disconnected known components remain independent allocations, and the live solver does not model cable thermal limits or cable-level throughput. The fixed source is an always-available 10 kW device, not a fuel/generator system. Battery energy redistribution within an APC component is deterministic and aggregate; the model does not simulate electrical priority between individual APC batteries and individual lamps.

Focused pure service tests cover two sources/two substations/two APCs with one shared lamp, source removal, a cut/unknown port, tier isolation, breaker behavior, battery discharge, and grid charging. The shared-component case verifies that two 5 kW sources deliver 10 kW total to the two substations (not 5 kW), and checks the downstream 4 kW aggregate APC input, 100 W shared lamp load, and 2 kJ aggregate battery charge. These are not GameTests and make no claim about in-world lifecycle behavior. Device indexing intentionally has a hard 512-device ceiling; excess devices remain unpowered until lifecycle policy is expanded. No manual server launch was performed.
