# M9 — pure starter-station power plan

## Scope and geometry

`StarterStationPowerPlan` remains a deterministic immutable geometry plan. `StarterStationService` now consumes it only on its existing new-world SavedData path. Preflight requires the complete footprint/circuit chunks to be FULL without requesting chunks, validates support/structure/device/host plans and cable attachment face tiers read-only, and rejects foreign occupants before writes. Cable authorization uses the planned host identity (steel, either station-floor finish, or an explicit extra steel host), not the block that happens to exist before placement: a dry replaceable current state may be the predicted host after structure placement, but fluid and nonreplaceable wrong hosts are rejected. Existing persisted cable tiers must be absent or match the plan; conflicting tiers fail preflight. Placement applies structure before overlays, then steel hosts, device states and cable records; exact devices are accepted by kind/facing irrespective of mutable lamp `LIT`, and existing exact cables are skipped. Completion follows circuit verification, allowing interrupted placement to resume without replacing persisted device block entities such as APC battery/breaker state.

The southwest bay contains an HV source at `(1,1,13)` facing west, an HV/MV substation at `(1,1,15)` facing west, and an APC at `(1,1,17)` facing east. HV cable runs on the steel west perimeter at x=0, z=13..15. MV cable uses three explicitly planned steel cable-host blocks at x=2, y=1, z=15..17. APC cable rises on the west wall at x=0, z=17, y=1..4, then turns onto an UP-facing floor cable. Four lamps occupy y=4 at the northwest, northeast, southwest and southeast room positions. Each has a vertical cable run on its specified wall and a distinct edge-turn to its tiled/floored lamp drop.

Since M14, a face may independently carry HV, MV, and APC simultaneously. Starter-plan preflight rejects only a duplicate complete host-face-tier key that conflicts with that exact planned cable; unrelated tiers already on the same face do not block the planned tier. It does not impose the historical M2 one-tier-per-face rule.

The APC floor network is a deterministic union of shortest four-neighbor BFS paths. It starts at local floor `(1,17)` and connects all four lamp drops, searching only interior coordinates that have an explicit layout floor cell. Cable nodes are unique host/face/tier tuples, within the footprint and y=0..4; distinct voltage tiers never become connected by topology. The maximum cable node count is bounded at 96. The existing station layout remains unchanged: all floor cells retain their floor material, rooms and entrance remain passable, and lamps sit in the four-high clear volume at y=4.

## Topology and material evidence

The tests use `PowerDeviceKind.ports`, `PowerTopology.deviceAdjacent`, and `PowerTopology.cableEdge` directly. Every defined device port must contact a matching-tier opposing cable face, and each tier's planned cable set must form a connected component solely through actual geometric cable edges. They also check cable host positions against steel or either tiled floor material in `StarterStationLayout` (or the plan's additional steel hosts), reject same-face conflicts, and exercise predicted dry-replaceable host authorization versus fluid/nonreplaceable rejection. Lamp positions, drops, bounds, immutability, and the cable-count bound are also asserted. There are no inferred links through solids or voltage-conversion shortcuts; HV/MV and MV/APC transitions are represented only by the respective device ports.

The lifecycle GameTest asserts completion of the new-world marker, all 400 tiled floors, all seven device identities/facings, every planned cable record, the room and entrance, then allows up to 120 additional ticks for runtime convergence and checks all four lamp `LIT` states and blockstate light emission against the existing `PowerSimulationGate` setting (lit/emission 14 when enabled, dark/emission 0 when disabled). It skips cleanly when no fresh-world marker is present. In the fresh-world automated server run recorded below, its enabled-gate assertions passed, establishing in-engine evidence for station generation, planned circuitry, and all four lamps converging lit. This is not manual client/sprite/visual or multiplayer acceptance. Restart resilience in an actual server and owner visual acceptance remain follow-up work; this change does not mutate shared topology/runtime/storage, configuration, atmospherics, or player code.
