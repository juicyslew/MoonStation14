# Sable authored plot proof — initial implementation

This is a stock-Sable assembly/operating-envelope proof, not a flight/body seamlessness or systems integration claim. `SableFixturePlot` allocates a server sublevel at an explicit world pose, writes at `plot.getCenterBlock()` storage coordinates through parent `ServerLevel.setBlock`, and rejects storage outside the engine-reserved plot before parent mutation. Normal authored callers use `allocateAndAuthor`: its server-thread callback synchronously writes the full assembly, then a private one-shot finalizer preserves the requested engine-projected anchor with one public native-body teleport and seeds Sable's last-pose/bounds snapshots before returning the plot. The public raw `allocate` path remains solely for the precision diagnostic that intentionally measures unfinalized mass/pivot shifts. No caller can invoke finalization late, and there is no per-frame correction, native fork, map rebasing, world-spawn change, gravity/lock workaround, or shipped coordinate clamp.

API mapping was checked against Sable NeoForge 2.0.6 release artifact SHA-256 `9c199157843bf953a47dff625fc5bb41c01a90538d35ad18e6996bbcb8a617c2` (digest transcription corrected; see `SABLE-INVENTORY.md`); release source tag target is `ad8b4d377741fbd923f4d863b2cf9e462daff9a6`. `ServerLevelPlot` / `EmbeddedPlotLevelAccessor` coordinate mapping was additionally supplied and verified from release bytecode: embedded local block coordinates are offset by `getCenterBlock()` and delegated to parent Level `setBlock`; `newEmptyChunk` takes global storage chunks, while `getChunk` takes local plot chunks. Runtime primitive and cabin fixtures exercise normal MoonStation BE initialization on this path.

Pose3d is Sable's public allocation signature and comes from the exact 1.6.0 Companion archive embedded by Sable. Its projection is `(storage - rotationPoint) * scale`, rotated, then translated by position. Sable retains the supplied pose without resetting its pivot, so the adapter sets the authored plot storage origin as `rotationPoint` and calls the public `ServerSubLevel.updateLastPose()` because Sable registers the physics body and copies its initial pose before `allocateNewSubLevel` returns. The tests use `logicalPose().transformPosition(storageOrigin)` rather than duplicating pose math. A narrow compile-only dependency uses the official RyanHcode Maven repository; it does not bundle or shade Companion. The existing `BoundedGameTestWait` scheduler is reused. `REMOVED` is used for engine-owned fixture cleanup.

## Stock precision operating envelope

The target envelope uses authored world bases near `(200,300,200)` and at approximately 5 km radius `(5200,300,200)` in the isolated GameTest dimension; it does not move or configure a user's world spawn. `SableFixtureScene` reuses the existing `FixtureChunkTickets` lease and bounded loaded/empty/in-bounds preflight, owns a small temporary physical support pad, and removes that pad on pass/failure. `SableOperatingEnvelopeGameTests` reuses `ShuttleCabinFixture.build`, waits on the real 100 W alarm / 20 W airlock readiness path, checks the finalized world anchor within 0.002 m before ticks and within 2 m after readiness/motion, and requires positive projected X/Z motion after one bounded native XYZ velocity nudge. It also verifies paid delivery, stable engine/BE identities, finite pipe gas ownership, and the finite room mixture at its existing authored storage cells. These are construction/test-only fixtures, not a new fixed-radius gameplay cap.

Single-precision boundary motivation: f32 spacing grows with absolute coordinate, so geometry near a shared origin and a site about 5,000 blocks away are representative samples; they do not define a universal radius guarantee. Earlier million-coordinate physical-cabin runs produced 5.17–8.47 m projected drift and remain out-of-scope diagnostics, not an acceptance limit or proof that every large-coordinate setup behaves identically. The separate `sable-precision` paired test intentionally retains the near-zero/million-scale comparison and emits measured state; those large-coordinate samples are not gameplay acceptance. No claim is made for arbitrary farther distances, connected clients, actor carry, cargo-on-moving-cabin, docking, FTL, or performance.

## Paired native-coordinate precision diagnostic

Added `sable-precision` GameTest using the same four-block floor/real two-high airlock geometry at a near-zero projected world pose and the actual GameTest helper's million-block-scale projected pose. Both fixtures use unique Sable plots and entity-ticking chunk leases; world projection volumes are preflighted as loaded, empty, in-bounds, and within build height. It records JSON lines (`MS14_SABLE_PRECISION`) at allocation, after first floor block, after complete geometry before the subsequent native tick, and after four native ticks with the same one-shot (+0.5,+0,+0.5) velocity. It checks finite measurements, accepted positive X/Z native velocities in both cases, actual positive projected X/Z movement for the near-zero case, and stable plot/airlock storage identity in both. Far-world projected movement is measurement-only and deliberately has no positive-displacement requirement.
